# データ作成手順（沖縄県PDCA 令和4〜7年度）

沖縄県が公表している「沖縄県PDCA実施結果」の総括報告書（PDF）から、公開サイトで使うデータを作る手順と、その途中で決めた読み方・計算方法をまとめる。
同じ手順で誰でも作り直せること、また数値の意味を取り違えないことが目的。

- 対象: 新・沖縄21世紀ビジョン実施計画の期間の報告書（令和4〜7年度対象。R4＝2022年度）
- 対象外: 平成24年度〜令和3年度（旧計画）。施策体系が違うので別に扱う
- 数値の根拠は常に県の報告書。このリポジトリの値と報告書が食い違えば報告書が正しい

## 1. 全体の流れ

```
県サイト ──取得──▶ data/raw ──zip展開──▶ data/interim ──抽出──▶ data/extracted ──ビルド──▶ site/dist
          fetch_pdca.py       expand_zips.py          extract_soukatsu.py      Astro（site/）
                                                       └─ check_extracted.py（公表値との突き合わせ）
```

| 手順 | コマンド | 実行場所 |
|---|---|---|
| 1. 取得 | `make fetch`（`python3 scripts/fetch_pdca.py`） | ホストの python3（標準ライブラリのみ） |
| 2. zip展開・抽出・突き合わせ | `make extract` | 解析用コンテナ（`docker/tools`。pdfplumber 0.11.10 / PyMuPDF 1.28.2） |
| 3. 突き合わせだけ | `make check` | ホストの python3 |
| 4. サイトの書き出し | `make build` | Node コンテナ（Astro 7） |

抽出結果（`data/extracted/soukatsu/*.json`）はコミットする。サイトはこれだけを読んでビルドするので、PDF が手元に無くてもサイトは作れる。

## 2. 元データ（総括報告書）

### 2.1 掲載場所とファイル

県サイトの「沖縄県PDCA実施結果（対象年度：令和N年度）」のページ。年度ごとにファイルの分け方と形式が違う。

| 対象年度 | 公表 | 本文（将来像1〜5）の形式 |
|---|---|---|
| R4（2022） | 令和5年 | 7本すべて zip（中にPDF） |
| R5（2023） | 令和6年 | PDF 6本 ＋ 将来像5だけ zip |
| R6（2024） | 令和7年 | PDF 3本 ＋ zip 3本 |
| R7（2025） | 令和8年8月 | PDF 6本 |

どのファイルが本文・付属資料かは、`manifest.jsonl` に記録した**リンク文言**で判定する（「将来像」を含む → 本文、「付属資料」→ 付属資料）。ファイル名は年度ごとにばらばらなので使わない。
zip は `data/interim/soukatsu/<年度>/<zip名>/` に展開し、出典は zip の URL と中のファイル名で表す（zip の中のPDFはページ指定でリンクできない）。

### 2.2 報告書の構成と、どこから何を取るか

| 部分 | ページの見分け方 | 取る項目 |
|---|---|---|
| 基本施策総括 | 表の先頭が「基本施策」、または本文に「基本施策 / コード / 名前 / 目指す姿」 | 基本施策のコード・名前・目指す姿 |
| 施策総括表（**R5から**） | 「主な取組数」と「順調の割合」がある | 施策ごとの推進状況（A〜G）の文言、主な取組の内訳（件数） |
| 様式２（施策） | ページ上端に「様式２（施策）」 | Ⅰ 主な取組、Ⅱ 成果指標、Ⅲ 分析（Check）、Ⅳ 推進戦略案（Action） |
| 付属資料 | リンク文言 | 主要指標一覧、将来像の名前 |
| 概要版 | （抽出しない） | 突き合わせ用の公表値（`check_extracted.py` に転記） |

部局別の「主な取組検証票（様式1）」「成果指標検証票（様式3）」は、この手順ではまだ使っていない（予算事業名・財源・当初予算などが載っている。今後の拡張）。

## 3. 施策体系とID

将来像（5）→ 基本施策（36）→ 施策展開 → 施策（339）→ 主な取組（R4〜R6: 1,539、R7: 1,534）。
施策は4年度とも同じ339件で、コードも変わらない（名前が変わったのは 3-(4)-ア-③ の1件だけ）。

コードは報告書の表記（全角・丸数字）を正規化して ID にする。

| 報告書の表記 | 正規化 | ID |
|---|---|---|
| 基本施策 `１－（１）` | `1-(1)` | `1-1` |
| 施策展開 `１－（１）－ア` | `1-(1)-ア` | `1-1-a`（ア→a、イ→b、ウ→c …の五十音順） |
| 施策 `１－（１）－ア－①` | `1-(1)-ア-1`（NFKC で丸数字も数字になる） | `1-1-a-1` |

表示用のコードは `1-(1)-ア-①` の形で持つ（`shisaku.json` の `code`）。

## 4. 抽出の規則

`scripts/extract_soukatsu.py` が行う。表は pdfplumber の表抽出、本文の行は pdfplumber の行抽出（座標つき）、ページの判定と回転ページの読み取りは PyMuPDF。

### 4.1 主な取組（様式２のⅠ）

- 表の1行目に「番号・取組名(所管部課)・決算見込額・活動指標・活動概要」、次の行に「目標・実績・進捗状況」が入っている。2行で1件として組み立てる。表がページをまたいでも続けて読む。
- 「○〜」で始まる行は施策の小項目。続く取組の `group` に入れる。
- 取組名と所管部課は、**末尾の括弧**で分ける（取組名自体が括弧を含むことがあるため）。
- 所管部は所管部課の先頭から取る（`知事公室|県警本部|警察本部|教育庁|企業局|病院事業局` のいずれか、なければ最初の「〜部」）。
- 決算見込額は千円単位の数値。「―」は空（null）。
- **同じ取組が複数の施策に載っている（再掲）ことがある**（例: 「地域や島でのシンポジウムや座談会の開催」は 1-(4)-ア-③ と 1-(5)-ア-⑤ の両方）。県の取組数は「再掲を含む延べ件数」（R4 概要版）なので、施策ごとに1件として数える。
- **進捗状況が空欄・「-」の取組がある**（事業廃止、基地関係の要請など）。取組としては残し、`status` を空、`status_raw` に元の表記を入れる。サイトでは「記載なし」と表示する。

### 4.2 成果指標（様式２のⅡ）

- 「成果指標名」の見出し行から6行で1組（見出し・年度・値・実績値の参照年・「計画値」・計画値）。1施策に最大4組ある（R7: 1組296施策、2組36、3組5、4組2）。
- 列の位置は見出し行の文字（単位・基準値・実績値・目標値・達成率・達成状況）から決める。年度によって列数が違う（9列と10列）。
- **実績値は計画期間の年度ごとに3列**ある（R4〜R6 または R7〜R9。R6の報告にはR4・R5・R6の3列が並ぶ）。値が入っている最後の列を「その報告時点の最新値」とし、3列すべてを `actual_series` に残す。
- 実績値の下の行は、その値が何年の値か（例: `R6年度`）。統計の公表が遅れる指標では報告年度より前の値になる。
- 達成率は「40.7%」のような数値のほか、「達成」「未達成」「-%」と書かれることがある。数値のときだけ `rate` に入れ、表記は `rate_raw` に残す。

### 4.3 施策の推進状況（施策総括表、R5から）

- 総括表で、成果指標の表と「主な取組数」の表のあいだの欄に印字された文言（例: 「取組は順調だが、成果は遅れている」）を読み、A〜G に対応させる（下の 6.3 の区分表）。
- 施策の番号（①②…）は同じ段の左端、施策展開のコードはその上の見出しから取る。前のページから続くページには施策展開の見出しが無いので、直前のページの値を引き継ぐ。
- 施策総括表と様式２が**別ファイル**のことがある（R7 は将来像3の総括表が `shouraizou3_1`、3-(6)以降の様式２が `shouraizou3_2`）。年度単位で突き合わせる。
- 同じ表の「主な取組数」の内訳は `summary_counts` に入れる。4.1 で数えた取組の内訳と比べて読み取り漏れを確認できる。
- R4 は施策ごとの判定が公表されていない（概要版に区分ごとの件数だけ）。

### 4.4 県の分析・推進戦略（様式２のⅢ・Ⅳ）

- ページを上から見て、行頭が「Ⅲ」「Ⅳ」の見出しの位置で区切り、表の外にある行を集める。ページをまたいで続く。
- PDF の折り返しを戻す: 前の行が右端（x≒556）まで来ていれば同じ段落の続き、そうでなければ改行。行頭が「・」「[」「【」「○」「①〜⑳」「※」なら必ず改行。

### 4.5 基本施策・将来像・主要指標

- 基本施策は総括ページの表から取る。**R4 の基本施策総括ページは回転して配置されていて、表として読むと文字が逆順になる**ため、PyMuPDF のテキストから正規表現で取る。
- 目指す姿は「目指す姿」の後ろから「〜目指す。」まで。
- 将来像の名前と主要指標は付属資料の「主要指標一覧」から。主要指標は1行に複数の指標（男女別、離島・過疎地域別など）が入ることがあり、文字のまま持つ。PDF の欄の中で文字が途中で切れているもの（例: 2-(8) の「[生産年齢人口割合]小」）は、報告書の時点で切れている。

### 4.6 既知の読み取り上の問題と対処

| 内容 | 対処 |
|---|---|
| R5 の 3-(9)-ア-① で「施策の方向」の続きが「関係部等」の欄に食い込んで読める | 関係部等の値に句点があれば、句点までを施策の方向に戻す |
| 進捗状況の欄が空欄・「-」（R5: 3件、R6: 15件、R7: 3件） | 「記載なし」として残す（6.6） |
| R5 の空欄のうち1件は、PDF 上に文字自体が無い（県の集計では「順調」） | 補わない |

## 5. 出力ファイル（`data/extracted/soukatsu/`）

すべて JSON 配列（1行1レコード）。どのレコードも `year`（西暦の年度）と出典（`source`: sources.json の ID、`page`: PDF のページ番号）を持つ。

| ファイル | 1件の単位 | 主な項目 |
|---|---|---|
| `shouraizou.json` | 年度×将来像 | `id`(1〜5), `name` |
| `kihon.json` | 年度×基本施策 | `id`(例 `1-1`), `code`, `name`, `mezasu`（目指す姿） |
| `shisaku.json` | 年度×施策 | `id`, `code`, `name`, `kihon_id`, `tenkai_id`, `tenkai_name`, `kankei`（関係部等）, `houkou`（施策の方向）, `check`, `action`, `judge`（A〜G）, `judge_label`, `summary_counts`, `summary_ref` |
| `torikumi.json` | 年度×主な取組 | `shisaku_id`, `no`, `name`, `key`（年度をまたぐ照合用）, `section`（所管部課）, `dept`（所管部）, `group`, `budget`（決算見込額・千円）, `budget_raw`, `indicator`（活動指標）, `target`, `actual`, `status`, `status_raw`, `summary`（活動概要） |
| `seika.json` | 年度×成果指標 | `shisaku_id`, `name`, `unit`, `base`/`base_raw`, `actual`/`actual_raw`, `actual_year`, `actual_ref_year`, `actual_series`, `plan`/`plan_raw`（計画期間3年分）, `target`/`target_raw`, `target_year`, `rate`/`rate_raw`, `judgement`（見通し）, `dept`（担当部課）, `explanation` |
| `shuyou.json` | 年度×主要指標の行 | `kihon_id`, `name`, `base_raw`, `actual_raw`, `target_raw`, `judgement` |
| `sources.json` | 入力ファイル | `id`, `file_url`, `link_text`, `page_url`, `page_title`, `kind`, `zip_member` |

`*_raw` は報告書の表記そのまま、対になる名前は数値に直したもの（「,」を外し、「△」はマイナス。読めなければ null）。

## 6. 年度による違い（計り方・計算方法）

### 6.1 計画期間が R6 と R7 の間で切り替わる

| | 前期実施計画 | 中期実施計画 |
|---|---|---|
| 報告の対象年度 | R4・R5・R6 | R7（〜R9） |
| 成果指標・主要指標の目標年度 | R6 | R9 |
| 各年度の計画値（成果指標） | R6目標値 −（R6目標値 − 基準値）× 残年数 / 3 | R9目標値 −（R9目標値 − 基準値）× 残年数 / 6 |

R7 で指標そのものと基準値・目標値が見直されている。数えると:

- 成果指標: R6→R7 で同じ名前のまま続くのは 299 / 389。そのうち基準値が変わったもの 153、目標値が変わったもの 256。52施策で成果指標の組み合わせが入れ替わった。
  - 例: 二酸化炭素排出量（主要指標）は前期が基準 1,159万t（R元年度）・目標 982万t（R6）、中期が基準 1,032万t（R3年度）・目標 876万t（R9）。
- 主な取組: R4→R5→R6 は全件が同じ名前で続く。R6→R7 で同じ名前のまま続くのは 1,346 / 1,534。R7 で新しく出た 188、R6 で最後になった 193（名前の変更を含む）。

**達成率は計画期間をまたいで比べない。** 同じ指標でも基準値・計画値が違う。実績値そのものの推移は通しで見てよいが、参照年（6.4）に注意する。

### 6.2 判定・区分の定義（概要版の記載）

**主な取組の進捗状況**（活動指標の実績が年度別計画に対してどこまで進んだか）

| 区分 | 基準 |
|---|---|
| 順調 | 年度別計画どおり又はそれ以上（90%以上） |
| 概ね順調 | 75%以上90%未満 |
| やや遅れ | 60%以上75%未満 |
| 大幅遅れ | 60%未満 |
| 未着手 | 年度別計画に示した活動に未着手 |

**成果指標の達成率**（4年度とも同じ）

```
達成率 = （その年度の実績値 − 基準値）/（その年度の計画値 − 基準値）× 100
```

基準値より悪ければマイナスになる。概要版はこの達成率で「100%以上 / 60%以上100%未満 / 0%超60%未満 / 0% / 0%未満」に分けて集計している。

**主要指標の達成率**

```
達成率 = （実績値 − 基準値）/（目標値 − 基準値）× 100      目標値は前期R6、中期R9
```

**前進・横ばい・後退**（主要指標・成果指標とも）: 基準値と直近の実績値を比べて「良くなっている／変わらない／悪くなっている」。統計がまだ出ていないなどで比べられないものは「その他」。

**目標の見通し**（成果指標の「達成状況」欄）: 目標達成 / 目標達成の見込み / 達成に努める / 達成は困難 の4つ。

### 6.3 施策の推進状況（A〜G）

県は施策ごとに【Ⅰ】主な取組のうち「順調」の割合と、【Ⅱ】成果指標の計画値に対する達成率を組み合わせて判定している（概要版「施策評価の判定基準」区分表。境目は40%と80%）。

| 区分 | 文言 |
|---|---|
| A | 順調 |
| B | 概ね順調 |
| C | 取組は順調だが、成果は遅れている |
| D | 取組は概ね順調だが、成果は遅れている |
| E | 成果は順調だが、取組は遅れている |
| F | 成果は概ね順調だが、取組は遅れている |
| G | 大幅遅れ |

- 区分表の境目で自分たちで計算し直すと、印字された判定と合わない施策がある（R7で66施策。「順調」の割合が80%未満でも A と印字されているもの）。境目の細かい扱いが公表されていないため、**判定は計算せず、施策総括表の印字をそのまま使う**。
- 県の集計には、どの区分にも入れない「その他」（災害対応・基地問題など対外的な関係で効果が出る施策、成果指標を設定しにくい施策、実績値が基準値と変わらない施策。R5: 11、R6: 3、R7: 3）がある。施策総括表にはこれらにも A〜G の文言が印字されているので、印字どおりに数えると区分ごとの件数が概要版と数件ずれる。

### 6.4 実績値の年がずれる

成果指標・主要指標の「実績値」は、報告の時点で分かっている最新の値。統計の公表時期の都合で、報告年度より前の値のことが多い（例: R7 報告の二酸化炭素排出量は R5年度の値）。何年の値かは `actual_ref_year` に入れている（空のものは報告年度の値と読める表記がない）。

### 6.5 報告書の値が式と合わないもの

`check_extracted.py` で、6.1・6.2 の式で計算し直して報告書の値と比べている。

| 年度 | 計画値: 式どおり / 式と違う | 達成率: 式どおり / 式と違う / 計算できない |
|---|---|---|
| R4 | 343 / 36 | 259 / 0 / 134 |
| R5 | 342 / 36 | 297 / **25** / 71 |
| R6 | 342 / 36 | 296 / 2 / 95 |
| R7 | 338 / 40 | 296 / 2 / 93 |

- 計画値が式と違う指標（各年度36〜40）は、段階的な目標や累計の指標など。計画値は報告書の値をそのまま使う。
- **R5 の達成率は25件が式と合わない。** 実績値 ÷ 目標値で計算したと見られるもの（例: さとうきび生産量 687,698 ÷ 858,647 = 80.1%）や、式では50.8%になるのに「100%」と書かれているもの（起業家育成数）がある。サイトは報告書の値をそのまま表示する。
- 「計算できない」は、達成率が「達成」「未達成」「-%」の文字のもの、基準値・実績値・計画値のどれかが数値で読めないもの、計画値＝基準値のもの。

### 6.6 公表値との突き合わせ

`make check` の結果（概要版の公表値と比べたもの）。

| 項目 | R4 | R5 | R6 | R7 |
|---|---|---|---|---|
| 基本施策 | 36 | 36 | 36 | 36 |
| 施策 | 339 | 339 | 339 | 339 |
| 主な取組 | 1,539 | 1,539 | 1,539 | 1,534 |
| 成果指標 | 393 | 393 | 393 | 391 |

件数はすべて一致する。差が出るのは次の2つで、理由は分かっている。

- 主な取組の進捗の内訳: 進捗状況の欄が空欄・「-」の取組を、県は「順調」「未着手」に数えている（R6 では「-」の8件が順調、空欄7件が未着手に入ると公表値と一致する）。
- 施策の推進状況（A〜G）: 6.3 の「その他」の扱い。

### 7.2 サイトでの扱い

- 部局ごとの集計は、**取組の最新年度の所管部局に寄せる**。年度をまたいで同じ取組とみなしたもの（7.3）は、R4 の分も R5 以降の所管部局で数える。R4→R5 は全取組が同じ名前で続くので、R4 の「子ども生活福祉部」「保健医療部」の取組はすべて再編後の部局に振り分けられる。
- 成果指標の担当部課（`seika.json` の `dept`）は年度ごとの表記のまま。R4 の旧部局名は、R4→R5 で取組が最も多く移った先の課に読み替えて部局ページに出す。

## 8. サイトでの計算方法

| 表示 | 計算 |
|---|---|
| 「順調」の割合 | その年度の「順調」の取組 ÷ その年度の全取組（「記載なし」も分母に入れる）。概要版の割合とは小数点以下で違うことがある |
| 成果指標の達成状況の区分 | 達成率が 100%以上／60%以上100%未満／0%超60%未満／0%以下。「達成」は100%以上、「未達成」は0%以下、「-%」など数値でないものは「達成率なし」 |
| 施策の判定の件数 | 施策総括表の印字を数えたもの（6.3） |
| 年度をまたいだ同じ取組 | 同じ施策の中で、名前が同じもの。比べるときは NFKC 正規化し、空白・「・」「、」「，」「,」「。」「.」「（）()」「「」『』〔〕」を除く（`key`） |
| 年度をまたいだ同じ成果指標 | 同じ施策の中で、同じ規則で正規化した名前が同じもの。同じ施策に同じ名前の指標が複数ある（男女別など）ときは出てくる順番で区別する |
| 取組の件数 | 延べ件数（再掲された取組は施策ごとに1件）。県の数え方と同じ |
| 遅れが続いている取組 | 進捗状況が「やや遅れ」「大幅遅れ」「未着手」の年度を数える。4年度とも報告にある取組のうち、4年とも遅れ／4年のうち3年遅れ |
| 決算見込額 | 取組ごとに表示するだけで**合計しない**。同じ予算事業の金額が複数の取組に重ねて書かれている（例: 県単融資の約657億円が3取組に同額） |

## 9. 作り直すとき

1. `make fetch` で報告書を取り直す（取得済みはスキップ。県が差し替えた場合は `--refresh`）。
2. `make extract` で展開・抽出・突き合わせ。`NG` が出たら件数が公表値と合っていないので、`警告` の理由（6.6）に当てはまるか、読み取りの不具合かを調べる。
3. 新しい年度（R8 以降）を足すときは、`scripts/check_extracted.py` の `EXPECTED` に概要版の公表値を書き足す。中期実施計画の2年目以降は、計画値の列の位置（`plan_index`）がずれることに注意。
4. `make build` でサイトを書き出す。
