# データ作成手順（沖縄県PDCA 令和4〜7年度）

沖縄県が公表している「[沖縄県PDCA実施結果](https://www.pref.okinawa.jp/kensei/shisaku/1014252/1014253/index.html)」の総括報告書（PDF）から、公開サイトで使うデータを作る手順と、その途中で決めた読み方・計算方法をまとめる。
同じ手順で誰でも作り直せること、また数値の意味を取り違えないことが目的。

- 対象: [新・沖縄21世紀ビジョン実施計画](https://www.pref.okinawa.jp/kensei/shisaku/1014211/1014230/index.html)の期間の報告書（令和4〜7年度対象。R4＝2022年度）。上位の計画は[新・沖縄21世紀ビジョン基本計画](https://www.pref.okinawa.jp/kensei/shisaku/1014211/1014223/1014250/index.html)
- 県の PDCA の入口: [沖縄県PDCA](https://www.pref.okinawa.jp/kensei/shisaku/1014252/index.html)（総括と部局別の検証票）
- 対象外: 平成24年度〜令和3年度（旧計画）。施策体系が違うので別に扱う
- 数値の根拠は常に県の報告書。このリポジトリの値と報告書が食い違えば報告書が正しい
- **取れていないデータと誤りの疑いがあるデータの一覧は [issues.md](issues.md)**（抽出データから自動で作る。`make issues`）

## 1. 全体の流れ

```
県サイト ──取得──▶ data/raw ──zip展開──▶ data/interim ──抽出──▶ data/extracted ──ビルド──▶ site/dist
          fetch_pdca.py       expand_zips.py          extract_soukatsu.py（総括報告書）   Astro（site/）
                                                       extract_bukyoku.py（部局別の検証票・予算）
                                                       extract_kanko.py / extract_ikkatsu.py / extract_hyoka.py（12章）
                                                       └─ check_extracted.py（公表値との突き合わせ）
```

| 手順 | コマンド | 実行場所 |
|---|---|---|
| 1. 取得 | `make fetch`（`python3 scripts/fetch_pdca.py`） | ホストの python3（標準ライブラリのみ） |
| 2. zip展開・抽出・突き合わせ | `make extract`（総括報告書・部局別の検証票・12章の評価） | 解析用コンテナ（`docker/tools`。[pdfplumber](https://github.com/jsvine/pdfplumber) 0.11.10 / [PyMuPDF](https://pymupdf.readthedocs.io/) 1.28.2） |
| 3. 突き合わせだけ | `make check` | ホストの python3 |
| 4. 欠け・誤りの一覧 | `make issues`（`make extract` の最後でも実行） | ホストの python3 |
| 5. サイトの書き出し | `make build` | Node コンテナ（[Astro](https://astro.build/) 7） |
| テスト | `make test`（抽出の関数と、サイトが前提にしていること） | 解析用コンテナ・Node コンテナ |

抽出結果（`data/extracted/soukatsu/*.json`）はコミットする。サイトはこれだけを読んでビルドするので、PDF が手元に無くてもサイトは作れる。

## 2. 元データ（総括報告書）

### 2.1 掲載場所とファイル

県サイトの「沖縄県PDCA実施結果（対象年度：令和N年度）」のページ（[年度別の一覧](https://www.pref.okinawa.jp/kensei/shisaku/1014252/1014253/index.html)。例: [令和7年度対象](https://www.pref.okinawa.jp/kensei/shisaku/1014252/1014253/1041342.html)）。年度ごとにファイルの分け方と形式が違う。

| 対象年度 | 公表 | 本文（将来像1〜5）の形式 |
|---|---|---|
| R4（2022） | 令和6年3月 | 7本すべて zip（中にPDF） |
| R5（2023） | 令和6年11月 | PDF 6本 ＋ 将来像5だけ zip |
| R6（2024） | 令和7年8月 | PDF 3本 ＋ zip 3本 |
| R7（2025） | 令和8年8月 | PDF 6本 |

どのファイルが本文・付属資料かは、`manifest.jsonl` に記録した**リンク文言**で判定する（「将来像」を含む → 本文、「付属資料」→ 付属資料）。ファイル名は年度ごとにばらばらなので使わない。
zip は `data/interim/soukatsu/<年度>/<zip名>/` に展開し、出典は zip の URL と中のファイル名で表す（zip の中のPDFはページ指定でリンクできない）。
県が zip を差し替えた場合に古い PDF が残らないよう、展開済みのファイルは中身（CRC）で比べて書き直し、zip から無くなったファイルは消す（`expand_zips.py`）。

### 2.2 報告書の構成と、どこから何を取るか

| 部分 | ページの見分け方 | 取る項目 |
|---|---|---|
| 基本施策総括 | 表の先頭が「基本施策」、または本文に「基本施策 / コード / 名前 / 目指す姿」 | 基本施策のコード・名前・目指す姿 |
| 施策総括表（**R5から**） | 「主な取組数」と「順調の割合」がある | 施策ごとの推進状況（A〜G）の文言、主な取組の内訳（件数） |
| 様式２（施策） | ページ上端に「様式２（施策）」 | Ⅰ 主な取組、Ⅱ 成果指標、Ⅲ 分析（Check）、Ⅳ 推進戦略案（Action） |
| 付属資料 | リンク文言 | 主要指標一覧、将来像の名前 |
| 概要版 | （抽出しない） | 突き合わせ用の公表値（`check_extracted.py` に転記） |

部局別の「主な取組検証票（様式1）」（[沖縄県PDCA](https://www.pref.okinawa.jp/kensei/shisaku/1014252/index.html)の各部局のページ）からは予算の記載だけを取る（11章）。「成果指標検証票（様式3）」はまだ使っていない。

## 3. 施策体系とID

将来像（5）→ 基本施策（36）→ 施策展開 → 施策（339）→ 主な取組（R4〜R6: 1,539、R7: 1,534）。
施策は4年度とも同じ339件で、コードも変わらない（名前が変わったのは 3-(4)-ア-③ の1件だけ）。

コードは報告書の表記（全角・丸数字）を正規化して ID にする。

| 報告書の表記 | 正規化 | ID |
|---|---|---|
| 基本施策 `１－（１）` | `1-(1)` | `1-1` |
| 施策展開 `１－（１）－ア` | `1-(1)-ア` | `1-1-a`（ア→a、イ→b、ウ→c …の五十音順） |
| 施策 `１－（１）－ア－①` | `1-(1)-ア-1`（NFKC で丸数字も数字になる） | `1-1-a-1` |

表示用のコードは `1-(1)-ア-①` の形で持つ（`shisaku.json` の `code`）。

## 4. 抽出の規則

`scripts/extract_soukatsu.py` が行う。表は pdfplumber の表抽出、本文の行は pdfplumber の行抽出（座標つき）、ページの判定と回転ページの読み取りは PyMuPDF。

### 4.1 主な取組（様式２のⅠ）

- 表の1行目に「番号・取組名(所管部課)・決算見込額・活動指標・活動概要」、次の行に「目標・実績・進捗状況」が入っている。2行で1件として組み立てる。表がページをまたいでも続けて読む。
- **目標・実績のセルが2行以上に分かれている取組がある**（北部と西表、件数と回数など。4年度で130取組）。番号・取組名・決算見込額・進捗状況・活動概要が空で目標か実績だけがある行を、前の取組の続きとして読み、`lines: [{target, actual}]` に印字の行ごとに入れる（空のセルは ""）。`target`・`actual` は空でない値を改行でつないだもの。前は1行目しか取っていなかった（例: R4 3-(8)-ウ-① の建設業経営力強化支援事業は「300件・12回」の行の実績が空で、2行目以降の「300件／325件」「12回／12回」が抜けていた）。サイトは行ごとに並べ、図や割合の棒には使わない。
- 「○〜」で始まる行は施策の小項目。続く取組の `group` に入れる。
- 取組名と所管部課は、**末尾の括弧**で分ける（取組名自体が括弧を含むことがあるため）。
- 所管部は所管部課の先頭から取る（`知事公室|県警本部|警察本部|教育庁|企業局|病院事業局` のいずれか、なければ最初の「〜部」）。
- 決算見込額は千円単位の数値。「―」は空（null）。
- **同じ取組が複数の施策に載っている（再掲）ことがある**（例: 「地域や島でのシンポジウムや座談会の開催」は 1-(4)-ア-③ と 1-(5)-ア-⑤ の両方）。県の取組数は「再掲を含む延べ件数」（R4 概要版）なので、施策ごとに1件として数える。
- **進捗状況が空欄・「-」の取組がある**（事業廃止、基地関係の要請など）。取組としては残し、`status` を空、`status_raw` に元の表記を入れる。サイトでは「記載なし」と表示する。

### 4.2 成果指標（様式２のⅡ）

- 「成果指標名」の見出し行から6行で1組（見出し・年度・値・実績値の参照年・「計画値」・計画値）。1施策に最大4組ある（R7: 1組296施策、2組36、3組5、4組2）。
- 列の位置は見出し行の文字（単位・基準値・実績値・目標値・達成率・達成状況）から決める。年度によって列数が違う（9列と10列）。
- **実績値は計画期間の年度ごとに3列**ある（R4〜R6 または R7〜R9。R6の報告にはR4・R5・R6の3列が並ぶ）。値が入っている最後の列を「その報告時点の最新値」とし、3列すべてを `actual_series` に残す。
- 実績値の下の行は、その値が何年の値か（例: `R6年度`）。統計の公表が遅れる指標では報告年度より前の値になる。
- 達成率は「40.7%」のような数値のほか、「達成」「未達成」「-%」と書かれることがある。数値のときだけ `rate` に入れ、表記は `rate_raw` に残す。

### 4.3 施策の推進状況（施策総括表、R5から）

- 総括表で、成果指標の表と「主な取組数」の表のあいだの欄に印字された文言（例: 「取組は順調だが、成果は遅れている」）を読み、A〜G に対応させる（下の 6.3 の区分表）。
- 施策の番号（①②…）は同じ段の左端、施策展開のコードはその上の見出しから取る。前のページから続くページには施策展開の見出しが無いので、直前のページの値を引き継ぐ。
- 施策総括表と様式２が**別ファイル**のことがある（R7 は将来像3の総括表が `shouraizou3_1`、3-(6)以降の様式２が `shouraizou3_2`）。年度単位で突き合わせる。
- 同じ表の「主な取組数」の内訳は `summary_counts` に入れる。4.1 で数えた取組の内訳と比べて読み取り漏れを確認できる。
- R4 は施策ごとの判定が公表されていない（概要版に区分ごとの件数だけ）。

### 4.4 県の分析・推進戦略（様式２のⅢ・Ⅳ）

- ページを上から見て、行頭が「Ⅲ」「Ⅳ」の見出しの位置で区切り、表の外にある行を集める。ページをまたいで続く。
- PDF の折り返しを戻す: 前の行が右端まで来ていれば同じ段落の続き、そうでなければ改行。右端は箱の縦の線から決める（線が無ければページの幅から。A4 で約544、R4 などの幅754〜773ptのページでは箱に合わせる。前は556に固定していて、幅の広いページでは小見出しが前の段落にくっついていた）。句点などで終わらない行は、右端の3文字手前まで来ていれば折り返しとみなす。行頭が「・」「[」「【」「○」「①〜⑳」「※」の行と、字下げした行（「外部環境の分析」などの小見出し）は必ず改行。英数字どうしをつなぐときは空白を入れる。
- **クリップで隠れた文字を読まない**。箱の外にはみ出してクリップで隠れた文字を pdfplumber は読むため、R5 1-(2)-ア-② の分析では約400字が2回入っていた（p53 の箱の下に隠れた文字と、p54 の箱に見える文字）。PyMuPDF の TEXT_CLIP で描かれる文字の位置を取り、それと重なる文字が1つも無い行はⅢ・Ⅳの本文から除く（表のセルは対象外。R5 3-(9)-ア-① の施策の方向は隠れた文字から戻すのが正しい。4.6）。

### 4.5 基本施策・将来像・主要指標

- 基本施策は総括ページの表から取る。**R4 の基本施策総括ページは回転して配置されていて、表として読むと文字が逆順になる**ため、PyMuPDF のテキストから正規表現で取る。
- 目指す姿は「目指す姿」の後ろから「〜目指す。」まで。「…目」「指す。」のように改行で分かれていても読む（前は 2-(4)・2-(5) の4年度と R6 の 5-(1) が空になっていた）。
- 将来像の名前と主要指標は付属資料の「主要指標一覧」から。主要指標は1行に複数の指標（男女別、離島・過疎地域別など）が入ることがあり、文字のまま持つ。サイトは図に置くために、ビルドのときに文字から数を読み取り、男女別などは見通しの欄の名前（「男性:目標達成」の「男性」）で分ける（`site/src/lib/data.ts` の `shuyouRows`）。PDF の欄の中で文字が途中で切れているもの（例: 2-(8) の「[生産年齢人口割合]小」）は、報告書の時点で切れている。

### 4.6 既知の読み取り上の問題と対処

- pdfplumber は、文字に変換できないグリフ（改行やタブの記号など）を「(cid:10)」のような文字列で出す。抽出のときに取り除く（`uncid`）。
- 施策コードを読めなかった様式２のページは、警告を出し、その施策の取組・成果指標・本文をどの施策にも付けない（前の施策に付かないように）。部局票で取組の見出しを読めなかったときも同じで、件数を `files.json` の `overview_failed` に記録する（現在0件）。


| 内容 | 対処 |
|---|---|
| R5 の 3-(9)-ア-① で「施策の方向」の続きが「関係部等」の欄に食い込んで読める | 関係部等の値に句点があれば、句点までを施策の方向に戻す |
| 進捗状況の欄が空欄・「-」（R5: 3件、R6: 15件、R7: 3件） | 「記載なし」として残す（6.6） |
| R5 の空欄3件（2-1-a-1・3-1-c-3・4-3-b-1）は、施策総括表の「主な取組数」の内訳ではどれも「未着手」に数えられている。一方、概要版の進捗の内訳（順調 1,185・未着手 19）は、このうち2件を「順調」、1件を「未着手」に数えた数と合い、県の資料の間で食い違う | 補わない（「記載なし」） |
| 成果指標の「達成状況の説明」の見出しと本文が次のページの頭に移っている（R5 1-(1)-ウ-④・1-(1)-ウ-⑤・2-(3)-イ-①） | 担当部課名だけ読めた指標を次の表まで持ち越し、次のページの「達成状況の説明」を付ける |
| 担当部課名・関係部等が欄の中で複数行に印字されている（R4・R5。3-(4)-ア-③、4-(3)-ア-② など） | 前の部分が課・部・局などで終われば「、」でつなぐ。「部の列＋課の列」を続けて書いた印字（R4 3-(4)-ア-③ の「商工労働部／土木建築部アジア経済戦略課／港湾課」など）は、部と課を上から順に組にする（組んだ結果が同じ施策の主な取組の所管部課と合うことを確かめた） |
| 見た目は普通の漢字だが、文字の中身が康熙部首（U+2F00〜）の字（R4 3-(11)-ウ-① の推進戦略案の「⽀援」「⼤学」） | 康熙部首とCJK部首補助の範囲の字だけを NFKC で普通の漢字に直す（`fix_chars`。部局票・観光ロードマップ・一括交付金の抽出も同じ）。`make check` は直っていない字を NG にする（6.7） |
| 1-(4)-ア-⑤ の活動概要などの「𥹥」（U+25E65。「歴史𥹥案館」） | 画像で拡大すると印字そのものが米偏の「𥹥」（正しくは「档」と思われる県の誤記）。印字どおり残す。Ext-B の字なので端末のフォントによっては表示できない |
| R5〜R7 の 5-(5)-イ-① の成果指標「宿泊事業者（正規雇用者）一人当たりの平均年収」の基準値が、列の幅が足りず「########」と印字されている | 文化観光スポーツ部の「成果指標」検証票に印字された値（3,129,946円。R4 の総括報告書と同じ）で補い、印字と出典を `base_fix` に残す（`extract_soukatsu.py` の `BASE_FIXES`）。補正表に無い「#」だけの基準値は警告を出す |

## 5. 出力ファイル（`data/extracted/soukatsu/`）

すべて JSON 配列（1行1レコード）。どのレコードも `year`（西暦の年度）と出典（`source`: sources.json の ID、`page`: PDF のページ番号）を持つ。

| ファイル | 1件の単位 | 主な項目 |
|---|---|---|
| `shouraizou.json` | 年度×将来像 | `id`(1〜5), `name` |
| `kihon.json` | 年度×基本施策 | `id`(例 `1-1`), `code`, `name`, `mezasu`（目指す姿） |
| `shisaku.json` | 年度×施策 | `id`, `code`, `name`, `kihon_id`, `tenkai_id`, `tenkai_name`, `kankei`（関係部等）, `houkou`（施策の方向）, `check`, `action`, `judge`（A〜G）, `judge_label`, `summary_counts`, `summary_ref`。`kankei` は欄の中で行が分かれた部局を「、」でつなぐ（4.6） |
| `torikumi.json` | 年度×主な取組 | `shisaku_id`, `no`, `name`, `key`（年度をまたぐ照合用）, `section`（所管部課）, `dept`（所管部）, `group`, `budget`（決算見込額・千円）, `budget_raw`, `indicator`（活動指標）, `target`, `actual`, `lines`（目標・実績が2行以上のときだけ。行ごとの `target`・`actual`。4.1）, `status`, `status_raw`, `summary`（活動概要） |
| `seika.json` | 年度×成果指標 | `shisaku_id`, `name`, `unit`, `base`/`base_raw`, `actual`/`actual_raw`, `actual_year`, `actual_ref_year`, `actual_series`, `plan`/`plan_raw`（計画期間3年分）, `target`/`target_raw`, `target_year`, `rate`/`rate_raw`, `judgement`（見通し）, `dept`（担当部課。欄の中で行が分かれたものは「、」でつなぐ。R6・R7 は印字どおり「,」）, `explanation`, `base_fix`（基準値を部局票の値で補ったときだけ: `printed`（総括報告書の印字）, `source`, `page`） |

部局別の検証票の抽出結果は `data/extracted/bukyoku/` に置く（11章）。

## 6. 年度による違い（計り方・計算方法）

### 6.1 計画期間が R6 と R7 の間で切り替わる

| | [前期実施計画](https://www.pref.okinawa.jp/kensei/shisaku/1014211/1014230/1014251.html) | [中期実施計画](https://www.pref.okinawa.jp/kensei/shisaku/1014211/1014230/1034436.html) |
|---|---|---|
| 報告の対象年度 | R4・R5・R6 | R7（〜R9） |
| 成果指標・主要指標の目標年度 | R6 | R9 |
| 各年度の計画値（成果指標） | R6目標値 −（R6目標値 − 基準値）× 残年数 / 3 | R9目標値 −（R9目標値 − 基準値）× 残年数 / 6 |

R7 で指標そのものと基準値・目標値が見直されている。数えると:

- 成果指標: R6→R7 で同じ名前のまま続くのは 299 / 389。そのうち基準値が変わったもの 153、目標値が変わったもの 256。52施策で成果指標の組み合わせが入れ替わった。
  - 例: 二酸化炭素排出量（主要指標）は前期が基準 1,159万t（R元年度）・目標 982万t（R6）、中期が基準 1,032万t（R3年度）・目標 876万t（R9）。
- 主な取組: R4→R5→R6 は全件が同じ名前で続く。R6→R7 で同じ名前のまま続くのは 1,346 / 1,534。R7 で新しく出た 188、R6 で最後になった 193（名前の変更を含む）。

**達成率は計画期間をまたいで比べない。** 同じ指標でも基準値・計画値が違う。実績値そのものの推移は通しで見てよいが、参照年（6.4）に注意する。

### 6.2 判定・区分の定義（概要版の記載）

**主な取組の進捗状況**（活動指標の実績が年度別計画に対してどこまで進んだか）

| 区分 | 基準 |
|---|---|
| 順調 | 年度別計画どおり又はそれ以上（90%以上） |
| 概ね順調 | 75%以上90%未満 |
| やや遅れ | 60%以上75%未満 |
| 大幅遅れ | 60%未満 |
| 未着手 | 年度別計画に示した活動に未着手 |

**成果指標の達成率**（4年度とも同じ）

```
達成率 = （その年度の実績値 − 基準値）/（その年度の計画値 − 基準値）× 100
```

基準値より悪ければマイナスになる。概要版はこの達成率で「100%以上 / 60%以上100%未満 / 0%超60%未満 / 0% / 0%未満」に分けて集計している。

**主要指標の達成率**

```
達成率 = （実績値 − 基準値）/（目標値 − 基準値）× 100      目標値は前期R6、中期R9
```

**前進・横ばい・後退**（主要指標・成果指標とも）: 基準値と直近の実績値を比べて「良くなっている／変わらない／悪くなっている」。統計がまだ出ていないなどで比べられないものは「その他」。

**目標の見通し**（成果指標の「達成状況」欄）: 目標達成 / 目標達成の見込み / 達成に努める / 達成は困難 の4つ。

### 6.3 施策の推進状況（A〜G）

県は施策ごとに【Ⅰ】主な取組のうち「順調」の割合と、【Ⅱ】成果指標の計画値に対する達成率を組み合わせて判定している（概要版「施策評価の判定基準」区分表。境目は40%と80%）。

| 区分 | 文言 |
|---|---|
| A | 順調 |
| B | 概ね順調 |
| C | 取組は順調だが、成果は遅れている |
| D | 取組は概ね順調だが、成果は遅れている |
| E | 成果は順調だが、取組は遅れている |
| F | 成果は概ね順調だが、取組は遅れている |
| G | 大幅遅れ |

- 区分表（概要版「施策評価の判定基準」区分表。R4〜R7 とも同じ）のマスは、縦が【Ⅰ】「順調」の割合、横が【Ⅱ】達成率で、次のとおり。A と B は「順調」の割合40%以上の2段にまたがる（サイトの `components/JudgeMatrix.astro` もこの置き方）。

  | 「順調」の割合 ＼ 達成率 | 80%以上 | 40%以上80%未満 | 40%未満 |
  |---|---|---|---|
  | 80%以上 | A | B | C |
  | 40%以上80%未満 | A | B | D |
  | 40%未満 | E | F | G |

- 施策総括表の「主な取組数」の内訳（`summary_counts`）と成果指標の達成率（2つ以上あれば平均。「達成」は100%、「未達成」は0%）からこの区分表で計算すると、印字された判定は R5〜R7 の計算できる施策すべて（R5 337・R6 336・R7 339）で一致する。判定・内訳・達成率の読み取りが互いに矛盾しないことの確かめにもなる。サイトは計算せず、印字をそのまま使う。
- 印字どおりに数えると、区分ごとの件数が概要版とずれる（R5: A 196/186、B 27/36 など。R7: A 197/194、B 48/50、C 55/53、その他 0/3。抽出/公表）。
  - 成果指標が2つ以上ある施策で、施策総括表は各指標の達成率をそのまま平均しているが、概要版の件数は各指標の達成率を100%で頭打ちにしてから平均した値で数えているとみられる（例: R7 の概要版の事例は 5-(5)-イ-② を B・達成率76.2% として載せていて、これは 111.4%（または114.4%）を100%にして 52.5% と平均した値。施策総括表の印字は A）。
  - 頭打ちにして計算し直すと、R7 は A 195・B 50・C 55・D 28・E 8・G 3 になり、概要版との差は A の1件と C の2件で、県が集計で「その他」に回した3施策の分と合う。R6 も A・C・E・F・G は概要版と一致する。
  - 県の集計の「その他」（災害対応・基地問題など対外的な関係で効果が出る施策、成果指標を設定しにくい施策、実績値が基準値と変わらない施策。R5: 11、R6: 3、R7: 3）は、施策総括表では A〜G が印字されている。どの施策かは公表されていない。

### 6.4 実績値の年がずれる

成果指標・主要指標の「実績値」は、報告の時点で分かっている最新の値。統計の公表時期の都合で、報告年度より前の値のことが多い（例: R7 報告の二酸化炭素排出量は R5年度の値）。何年の値かは `actual_ref_year` に入れている（空のものは報告年度の値と読める表記がない）。

### 6.5 報告書の値が式と合わないもの

`check_extracted.py` で、6.1・6.2 の式で計算し直して報告書の値と比べている。

| 年度 | 計画値: 式どおり / 式と違う | 達成率: 式どおり / 式と違う / 計算できない |
|---|---|---|
| R4 | 343 / 36 | 259 / 0 / 134 |
| R5 | 342 / 36 | 297 / **25** / 71 |
| R6 | 342 / 36 | 296 / 2 / 95 |
| R7 | 338 / 40 | 296 / 2 / 93 |

- 計画値が式と違う指標（各年度36〜40）は、段階的な目標や累計の指標など。計画値は報告書の値をそのまま使う。
- **R5 の達成率は25件が式と合わない。** 実績値 ÷ 目標値で計算したと見られるもの（例: さとうきび生産量 687,698 ÷ 858,647 = 80.1%）や、式では50.8%になるのに「100%」と書かれているもの（起業家育成数）がある。サイトは報告書の値をそのまま表示する。
- 「計算できない」は、達成率が「達成」「未達成」「-%」の文字のもの、基準値・実績値・計画値のどれかが数値で読めないもの、計画値＝基準値のもの。

|---|---|---|---|---|

### 6.7 2種類の読み取りの突き合わせと文字の検査

`make extract` の中で、抽出のあとに次の2つを動かす（2026-10 に PDF と抽出結果を全件突き合わせた検証で見つけた誤りの種類を、作り直すたびに見つけるため）。

- **`make cross-read`（`scripts/cross_read.py`。tools コンテナ、PDF が要る）**: 総括報告書の成果指標と主な取組を、抽出（pdfplumber）とは別の実装（PyMuPDF の `find_tables`）で読み直し、欄ごとに比べる。食い違いが1件でもあれば NG（終了コード1）で、`make extract` はそこで止まる。全年度で1分弱、`--year` で絞れる。
  - 比べる欄: 成果指標の `name`・`unit`・`base_raw`（`base_fix` のあるものは印字）・`actual_series` の値と参照年・`plan_raw`・`target_raw`・`rate_raw`・`judgement`、主な取組の `name`・`budget_raw`・`target`・`actual`・`lines`・`status_raw`。文字は空白・改行・「(cid:N)」を除いて比べる。
  - 表の行と列を決める実装が別なので、片方だけの読み違い（列のずれ、2行目以降の取りこぼし、隣の取組の混入）を見つけられる。どちらも PDF の文字の層を読むので、字の対応づけの誤り（下の文字の検査の対象外のもの）は見つけられない。説明・担当部課名、付属資料、部局票は対象外。
  - 読み直し側の癖で、ページの画像で抽出が正しいと確かめたものだけを、理由と日付つきで例外の表 `KNOWN` に足す（いまは R6 2-(5)-ウ-② の参照年の「.」を PyMuPDF が落とす1件）。
- **紛らわしい文字の検査（`make check`）**: `data/extracted` のすべての文字の値に、康熙部首（U+2F00〜U+2FDF）・CJK部首補助（U+2E80〜U+2EFF）・私用領域（U+E000〜U+F8FF）・置換文字（U+FFFD）・「(cid:」・改行とタブ以外の制御文字があれば NG。見た目は同じでも別の文字で、サイトの検索で当たらなくなるため（R4 3-(11)-ウ-① で見つかった）。印字と違う普通の字に対応づけられた字（例: U+25E65）は機械では見分けられない。
- サイトのテスト（`site/test/integrity.test.ts`）でも、施策総括表に印字された判定が、取組の内訳と成果指標の達成率から区分表（6.3）で計算したものと全施策で同じかを確かめる。判定・内訳・達成率のどれかの読み違い、区分表のマスの置き方の誤りで落ちる。

## 8. サイトでの計算方法

| 表示 | 計算 |
|---|---|
| 「順調」の割合 | その年度の「順調」の取組 ÷ その年度の全取組（「記載なし」も分母に入れる）。概要版の割合とは小数点以下で違うことがある |
| 成果指標の達成状況の区分 | 達成率が 100%以上／60%以上100%未満／0%超60%未満／0%以下。「達成」は100%以上、「未達成」は0%以下、「-%」など数値でないものは「達成率なし」 |
| 施策の判定の件数 | 施策総括表の印字を数えたもの（6.3） |
| 年度をまたいだ同じ取組 | 同じ施策の中で、名前が同じもの。比べるときは NFKC 正規化し、空白・「・」「、」「，」「,」「。」「.」「（）()」「「」『』〔〕」を除く（`key`） |

| 3年以上遅れた状態が続いている取組 | R5・R6・R7と続けて遅れていて、今も遅れている取組（トップの文章。取組の検索の「4年間の様子: R5からR7まで続けて遅れ」）。R7で遅れている取組の内訳になる |
| 決算見込額（施策ページ） | 取組ごとに部局票の予算事業・財源・金額を表示する。部局票が無い取組は総括報告書の決算見込額 |

## 9. 作り直すとき

1. `make fetch` で報告書を取り直す（取得済みはスキップ。県が差し替えた場合は `--refresh`）。
2. `make extract` で展開・抽出・突き合わせ。`NG` が出たら件数が公表値と合っていないので、`警告` の理由（6.6）に当てはまるか、読み取りの不具合かを調べる。
3. robots.txt で自動取得できないファイル（県企業局）は、ブラウザでダウンロードしてから取り込む。取得台帳にはリンクの記録だけが残っているので、
   `python3 scripts/import_manual.py <ダウンロードしたフォルダ> --source kigyo --since 2022` で、台帳の場所に置いて記録（sha256・`fetched_by: manual`）を埋める。
   そのあと `docker compose run --rm tools python scripts/extract_bukyoku.py --source kigyo` で企業局の分だけ読み直せる。
4. 一部の年度・取得元だけ読み直すときは `--year`（部局票は `--source` も）で絞れる。出力ファイルの他の年度・取得元の行は残して、その分だけ差し替える。
5. 新しい年度（R8 以降）を足すときは、`scripts/check_extracted.py` の `EXPECTED` に概要版の公表値を書き足す。中期実施計画の2年目以降は、計画値の列の位置（`plan_index`）がずれることに注意。
6. `make test` で、抽出の関数と、サイトが前提にしていること（名前の key の規則・出典・取組の URL・くらしのテーマ・部局のページ）が崩れていないかを確かめる。
7. `make build` でサイトを書き出す。

## 11. 予算・財源（部局別の主な取組検証票）

`scripts/extract_bukyoku.py` が、部局ごとに公開されている「主な取組」検証票（様式1）から予算の記載と、取組ごとの Plan・Do・Check・Action の記載を取る。総括報告書の様式２にも決算見込額・活動指標・進捗状況はあるが、予算事業名・財源・前年度決算額・翌年度当初予算額と、活動内容・判定の根拠・検証・改善案は部局票にしか無い（取組のページで使う。11.6）。

### 11.1 読み方

- 入力は `data/raw/<部局>/<年度>/` の PDF（soukatsu 以外）。様式1かどうかはページの中身（「施策展開」の見出しの表、「予算事業名」の表）で見分ける。成果指標検証票（様式3）のファイルは取組0件になる。
- 1ページ目の見出しの表から、施策展開のコード・施策の番号・取組名を取る。**見出しと値が別の行に入るファイルがある**ので、セルの位置ではなく値の形（`2-(6)-イ` のようなコード、①で始まる施策名）で探す。
- 「２ 取組の状況（Do）」の表は「予算事業名」から始まる塊で、左に前年度の決算額・当年度の決算見込額、右に翌年度の当初予算額が並ぶ（R7の報告なら R6決算額・R7決算見込額・R8当初予算額）。1つの取組に予算事業が複数あることがある（4年度分の延べで、2件のものが535、3件以上が19）。
- 財源の文字が折り返して次の行に続くことがある（「一括交付金」「（ソフト）」）。金額の無い行は前の行の財源の続きとしてつなぐ。
- 保健医療部などには、左（前年度決算額・決算見込額）と右（翌年度当初予算額）が別々の表になっているファイルがある。右だけの表は、同じ予算事業名の左の表の行に順に合わせる（`merge_right_only`）。前はこの右の表を読めず、翌年度当初予算額が抜けていた。
- 総括報告書の取組とは、施策コードと取組名（`key`、8章の正規化）で結び付ける。部局票にしか無い取組は0件（名前の照合がずれていない）。
- 総括報告書で別の施策にも再掲されている取組は、部局票では元の施策にしか載っていないことがある。同じ年度に同じ名前の取組が部局票に1件だけなら、名前で結び付ける（各年度1〜2件。issues.md の A2）。件数は、同じ取組が複数の部局のファイルに載っている分（R5 の12件）を除いてから数える（サイトの data.ts と report_issues.py で同じ）。
- 予算の表があるページ（取組の見出しとは別のページのことがある）を予算事業ごとに `page` に記録し、出典のリンクに使う。
- **予算の行がページの境目で切れて次のページに続く票がある**（4年度で8取組）。ページの最後の予算事業の下に「令和X年度活動内容」が無ければ、次のページの頭（最初の見出しより上）の文字を同じ列の位置で読んで続ける。左右が別の表のときは、予算事業名の書き方が違っていても、同じ高さの左の表の行と組にする（前は金額・財源が欠けたり、1つの予算事業が2件に分かれたりしていた）。
- **県のページに前の年度の票が掲載されていることがある**（R5 企画部 3-(12)-イ・商工労働部 3-(11)-エ、R6 商工労働部 3-(11)-エ・4-(3)-ア、R7 商工労働部 5-(4)-ア の5ファイル。4つは前の年度のファイルと SHA-256 も一致）。票の中身の年度を「令和X年度活動内容」と予算の表の「RX年度 決算見込額」の見出しから決め（`content_year`）、フォルダの年度と違えば取組を取り込まない（前は前の年度の金額・実績・検証を、その年度のものとして表示していた）。`files.json` に `content_year` と `note` を残す。その取組は「部局票が無い取組」（issues.md の A1）になる。
- 活動指標の表（「活動指標名」・過去2年の実績・達成割合）が2つ以上ある取組がある（4年度で129取組）。すべてを印字の順に `indicators` に入れ、`indicator_name`・`past`・`achievement` には最初の表（総括報告書の目標・実績の1行目に当たる）を入れる（前は最後の表だけを取っていた）。表の値の行が次のページに続く票、「実績値」の見出しが年度の行の側にある票も読む。
- 年度別計画の3年分が1つのセルに取れたときは、年度の見出し（R4・R5・R6）の位置で分ける（`split_by_years`）。取組の説明が「１ 県公用車を…」のように数字で始まる票は、見出しと取り違えないようにする。
- 表に重なって印字されたページ番号（達成割合の「28.6%-17-」の「-17-」）は取り除く。

### 11.4 合計の出し方

- **同じ予算事業が複数の取組に、同じ金額で書かれていることが多い**（例: 県単融資事業費 656.8億円が3取組、中部流域下水道事業会計等が9取組）。報告年度・金額の種類ごとに、予算事業名・財源・金額が同じものは1回だけ数える。名前が同じでも金額が違うものは別々に足す。
- 1つの予算事業が複数の取組に載っているときは、部局別・将来像別の集計では最初に出てくる取組（施策コード順）に寄せる。
- **桁の誤記と見られる金額は合計から除く。** 同じ行の3つの金額（前年度決算・当年度見込・翌年度当初）のうち1つが、0でない他の金額の50倍以上・10億円以上で、かつ他の年度の報告にある同じ予算事業・同じ年度の金額（例: R6の決算見込額に対して、R7の報告のR6決算額）に10倍以内の値が無いもの。現在2件で、サイトの「予算と財源」と issues.md の B1 に出典つきで一覧している（判定は `extract_bukyoku.py` の `suspect_kinds`・`confirm_suspects`）。
  - 事業の終了・開始の年は他の金額が0になるので、0とは比べない（前は0を1として比べていて、事業終了の年の決算額約10.4億円を誤って除いていた）。
  - 他の年度の報告で裏付けられたものは合計に入れる（例: R5 の報告の生活福祉資金貸付事業費の R4 決算額 64.7億円）。
  - 例: R6 の施策 3-(4)-ア-② の「国際物流関連産業推進費」の決算見込額が「75,107,510」（千円）と印字されている。同じ予算事業は施策 3-(12)-ウ-① では「7,510」。
- 県単融資事業費のように、貸付の原資（融資枠）を計上している事業も含む。
- 財源別の推移は、各報告のうち確定に近い金額を並べる: R3〜R6 は決算額（翌年度の報告に載るもの）、R7 は決算見込額、R8 は当初予算額。報告ごとに取組の範囲が違う（R7 で中期計画に入れ替わり、部局票の範囲も11.2のとおり違う）ので、増減は目安。

### 11.6 取組の詳細（Plan・Do・Check・Action）

取組のページ（`/torikumi/<施策>/<取組>/`）に出す、部局票の文章の欄。どれも票の文章をそのまま（PDF の折り返しの改行だけ戻し、「○」「・」「①」などで始まる行の前の改行は残す）。

| 欄 | 様式1 の場所 |
|---|---|
| 取組の説明・実施主体・年度別計画（活動指標と3年分の目標） | １ 取組の概要（Plan） |
| 当年度の活動内容・翌年度の活動計画 | ２ 取組の状況（Do）の予算の表の下。予算事業が複数ある取組は予算事業ごとに欄があるので、改行でつなぐ |
| 活動指標の過去2年の実績・達成割合 | 同じく「活動指標名」の表 |
| 進捗状況の判定根拠、要因及び取組の効果 | 同じく |
| これまでの改善案の反映状況（前年度の改善案と、その反映状況） | ２の（２） |
| 取組の検証（類型と内容） | ３ 取組の検証（Check） |
| 取組の改善案（類型と内容） | ４ 取組の改善案（Action） |

表の形がファイルによって違うので、次のように読む。

- **活動内容と活動計画が1つのセルとして取れる**ファイルが多い（2列の文章が交互に混ざる）。見出しの「令和X+1年度活動計画」のセルの左端の位置で、文章のセルを左右に切って読む（`read_activity`）。両方の欄に同じ文章が書かれている取組もある（票のまま）。
- **表がページをまたぐ**と、続きは見出しの無い表になる。どの欄の続きかを持ち越して読む（`read_status` の `state`）。見出しの無いページも、続きを読んでいる間は読む。改善案の反映状況は、続きの行が「○」などで始まらなければ前の行の続き（1つの欄がページで切れたもの）としてつなぐ。
- 「３ 取組の検証」「４ 取組の改善案」の**見出しが表の外の文字**になっていて、表が「類型・内容」から始まるファイルがある。表の上にある一番近い見出し（前のページの一番下にある見出しも持ち越す）で Check か Action かを決める。**Check と Action の表が左右に並ぶ**ファイルもあるので、見出しの横の位置も見る。左右に並んだまま次のページに続くときは、表の横の位置でどちらの続きかを決める。
- 確かめ方: Check の類型（「〜(内部要因)」「〜(外部環境の変化)」「〜(改善余地の検証等)」）が Action に入っているもの、その逆が0件であること。類型は Check 9種・Action 8種で、表記の揺れは無い。

**R7 で Check の類型が変わった。** R4〜R6 の「⑦その他(改善余地の検証等)」が、R7 では「⑦その他内部要因(改善余地の検証等)」と「⑧その他外部要因(改善余地の検証等)」に分かれた。年度をまたいで類型の件数を比べるときは、この2つを合わせる。

取れ具合（4年度の延べ 6,076取組のうち空のもの）: 活動内容 4、判定の根拠 7、改善案の反映状況 3、Check・Action 各2、翌年度の活動計画 89、達成割合 44。活動計画の空欄の多くは事業が終わった取組で、票でも空欄。それ以外は [issues.md](issues.md) の A9 に出典つきで一覧している。

### 12.1 観光ロードマップPDCA

- 実施報告書（本編）の「施策」総括表は、沖縄県PDCA の様式２とほぼ同じ形（Ⅰ 主な取組の進捗状況・Ⅱ 成果指標の達成状況・Ⅲ 分析（Check）・Ⅳ 推進戦略案（Action））。体系は観光ロードマップ独自の6基本施策・30施策展開・85施策。
- 施策のコードは「1-ア-①」→ `1-a-1`、施策展開「1-ア」→ `1-a`。基本施策5だけ施策展開に「ア・イ」の段が無い（「5」「5-①」→ `5`・`5-1`）。沖縄県PDCA の施策ID（`1-1-a-1`）とは別の番号なので、画面では必ず「観光ロードマップ」と付けて出す。
- 表は結合セルの None を除いて読む（年度で列の数が違っても同じに読める）。成果指標の目標値・達成率・達成状況は結合セルで、どの行に出るかが年度で違うので、指標の行の組（値の行・参照年の行・「計画値」の行・計画値の行）の中で最初に出てくる値を使う。名前が長い指標は2行目に名前の続き・単位・基準値が来る（R5 の基本施策5）。
- 見出しの「Ⅲ」は NFKC で「III」になる。「Ⅲ施策の…」と空白が無いこともある。
- **R4 の本編は読めない。** 218ページ中195ページが、文字の対応表（ToUnicode）の無い埋め込みフォント（MSゴシックの一部。cmap も無い）で書かれていて、pdfplumber でも PyMuPDF でも文字にならない。R4 は概要版の件数（`years.json`）だけを使う。成果指標の R4 の実績値は、R5・R6 の報告書の表にある。
- 公表値との突き合わせ（`years.json` に概要版の件数）: R5・R6 とも主な取組 291件・成果指標 100、進捗状況の内訳と「前進」の数が一致する。
- 沖縄県PDCA との照合（`pdca`）: 同じ年度に同じ名前（`key`）の主な取組。無ければ名前がよく似ていて（difflib で 0.85 以上）決算見込額も同じもの（`pdca_match: "similar"`）。R6 は 291件中 158件（R5 は 159件）が沖縄県PDCA にもあり、進捗状況もほぼ同じ（違うのは沖縄県PDCA 側の欄が空欄のもの）。成果指標は名前が同じものだけ（R6 は100のうち25）。
- **決算見込額は合計しない。** 同じ予算（観光統計の調査の 56,275千円など）が5件以上の取組に重ねて書かれている。予算と財源のページにも足していない。
- 1つのセルに金額が2行以上印字されている取組がある（R6 の 1-ウ-② No.3「316,411／113,189」など9件）。どう足すかが報告書に書かれていないので、`budget_raw` に行を改行でつないで残し、`budget` は null にする（前は数字をつないで桁外れの値にしていた）。サイトは行ごとに円で並べる。丸数字の内訳の後に和の合う値が続くもの（R5 3-エ-② No.2「①29,429 ②20,066 ③31,900 81,395」）は、その値を合計として `budget` に入れる（沖縄県PDCA の同じ取組 3-(2)-オ-② の R5 の決算見込額は 76,773 で、報告書の間で違う）。
- 成果指標の目標値は結合セルの全文を取る（前は「年間入域観」のように1行目だけだった）。実績値の下の行のかっこ書き（「3,681 (177,191)」「―(R8導入)」）は実績の表記に付け、数はかっこの前の値にする。
- 欄の中の改行は、2つの値を並べたもの（「10件(20件)」と「45件(90件)」、「北部:B」と「西表島:B」、箇条の「・」）だけ残し、PDF の折り返しは詰める（`cell_lines`）。
- 取組名と所管部課は入れ子の括弧（「（土木建築部港湾課（那覇港管理組合））」）にも対応して分ける。所管部課の後ろに書かれた小事業の一覧は `name_note` に入れる。

### 12.2 一括交付金（ソフト）の事後評価

- 総括表の「令和N年度事業評価結果個別事業」の表から、事業番号・名称・計画期間・事業概要・成果目標（目標・実績）・評価（◎達成・○概ね達成・△一部達成・未達成）・達成率を取る。列は見出しの名前で決める（R4 は成果目標と成果実績が文で1列ずつ、評価は事業の最後の行の結合セル。R5〜 は成果目標・目標・実績の3列）。2つの基本施策に再掲された事業（R5 の No.138）は事業番号で1件にまとめる。前年度の繰越事業と、事業完了後の検証（後年度効果発現事業）の章は読まない。
- 検証シート（基本施策ごとのファイル）から、施策のコード・担当部課名・予算（評価の年度の列の「計(b+d)」「執行済額」「うち交付金充当額」「執行率」）・今後の取り組み方針を取り、年度と事業番号で総括表に結び付ける。シートの見出しは文字で読む（罫線の無いシートは表として読めないため）。予算は、同じ高さに並ぶ「R4年度」「R4年度（繰越）」…の列見出しの中心の中間で列の範囲を区切り、その範囲の数字を取る（数字は右寄せのことがある）。
- 施策のコードの表記揺れ: `1-⑴-ｱ-①`（NFKC で `1-(1)-ア-1`）、`第４章－１－（１）－ア－①`、`3ー⑷ーイー②`（区切りがすべて長音記号）、`アー1`・`ア1`（区切りが長音記号・無い）、`➁`（NFKC で数字にならない丸数字）、`1―(4)―ウ`（施策展開まで）。施策展開までのものは、シートの「基本計画該当箇所」の施策名と同じ名前の沖縄県PDCA の施策にする。
- R5 の将来像2の一部の検証シート（子育て・離島・福祉などの14事業）は画像だけのPDFで読めない。施策のコード・担当部課・予算（計・執行済額・交付金充当額・執行率。執行率＝執行済額÷計で確かめた）は画像を目で読んだ表（`extract_ikkatsu.py` の `SHEET_FIXES`。出典のページつき）で与え、`shisaku_ref`（`printed`・`source`・`page`）と `sheet_image`（`source`・`page`・画像から読んだ欄 `fields`）に残す。今後の取り組み方針は長い文で読み違いのおそれがあるので空のまま。別の年度の同じ名前の事業のコードで補う（`shisaku_from`）のは、印字が施策展開までの R4 の6事業と R5 No.161 だけ。
- R4 の総括表には、事業番号を印字し直して次の段・次のページに続く事業がある。続きの成果目標と事業概要を前の分に足す（前は最初の段だけを残していて、No.126 などの未達の目標が抜けていた）。1つのセルが複数の小事業にまたがる成果目標は、小事業名（`part`）を付けない。
- 今後の取り組み方針（`policy`）は丸数字を残す（コードの読み取りだけ NFKC。前は「①②」が「12」になっていた）。R4 No.165 の担当部課の欄は「■当年度 □後年度（ 年度）」と誤って印字されているので空にする。担当部課が欄の中で2行以上に書かれたもの（R4 No.114 など14件）は、課の名前で終わった行の次に別の課が来るときだけ「、」で区切る。
- 公表値との突き合わせ: 評価した事業数と評価の内訳が R4（181）・R5（179）・R6（176）とも一致する（R6 は内訳のうち達成と概ね達成の合計だけが文章にある）。執行率は全件で「執行済額÷予算額」と合う。
- 主な取組とは結び付けていない。同じ事業でも名前や単位が違う（例: R6「ステップハウス運営事業」の執行済額 4,560千円は、主な取組「ＤＶ被害者等の支援」の決算見込額と同じ）。部局票の予算事業の名前でなら R6 の事業の6割ほど（176のうち109）が合うが、1つの予算事業が複数の取組（別の施策のものも）にまたがり、取組の進捗状況（活動の量）と事後評価（成果目標）で結果が食い違うことも多く、並べると利用者が混乱するので結び付けない。
