# デザインの決まり

ユーザーと決めた、サイト全体にかかわる見た目と見せ方の決まり。画面を変える・足すときは先に読む。ページごとの並びや部品の細かい形はここには書かず、コードとそのコメントに任せる。

## 1. 方針

- **県を批判するためのサイトではなく、状況を公平に確かめるためのもの。** 順調なもの・遅れているもののどちらかだけを選んで目立たせない（遅れの件数を大きく並べる・悪い順に並べる・良いものだけに絞ったリンクを置く、はしない）。全体の内訳を同じ重みで見せ、遅れている取組・判定が下がった施策・後退した指標などは、一覧の絞り込み（`?pat=delay3`・`?trend=down` など）で見たい人が見られるようにする。並びは報告書の順で、良い・悪いで並べ替えない。前の年度からの変化は、良くなったものと悪くなったものを対にする。
- **計画は3つの段で見せる。** 段ごとに、県がやること（もの）とそれをはかる物差しを組にする: 基本施策と主要指標（沖縄の姿）、施策と成果指標（施策の成果）、主な取組と活動指標（県の活動）。将来像は段ではなく、基本施策を束ねる枠。同じ段のものと物差しはいつも一緒に見せ、段をまたぐつながりはページの移り（ページの階層・子の一覧）で見せる。物差しどうしを縦に結ぶ図（成果指標が上がると主要指標が上がる、のような）は、県が決めていない結び付きになるので作らない。3つの段を一度に並べるのは、トップと将来像のページの頭（`components/Ladder.astro`。上から姿 → 成果 → 活動）と、指標のマップ（`/map/`）だけ。指標のマップは1マス＝1指標で、選んだ年度の県の区分で色分けする。3つを1つの枠にまとめ、将来像ごとの行に姿 → 成果 → 活動の順に並べる（PC は左から、スマホは上から）。PC では全部のマスがなるべく1画面に入るよう、将来像は行の左の丸の番号にする。列の見出しは「主要指標(49)」のような1行にし（数は絞り込むと条件に合う数にし、条件に合う数の行は画面に出さず読み上げだけにする）、県の報告書での呼び名（最終アウトカムなど）は、指標の名前を押すと出る用語の説明に足す。区分の意味が段ごとに違うので、マスは段ごとの箱に分けて混ぜず、凡例はマップの下の別の箱に段ごとの行で並べる（色でそろえた表にはしない。別の段の区分が同じ意味に読めるため）。年度はセレクトで選び、キーワード（計画の目次と同じ探し方）・くらしのテーマ・部局・段ごとの区分で絞り込める。段の問いの上には、県の報告書での物差しの呼び名（主要指標＝最終アウトカム、成果指標＝初期アウトカム、活動指標＝アウトプット。概要版の「新PDCA」の図と様式２の見出しの言葉）を小さく置き、押すと用語の説明を出す。くらしのテーマのページの頭も同じ形にするが、テーマと主要指標の対応をまだ決めていないので、成果指標と取組の2段にする。段の割合は意味が違う（主要指標は R9 のゴールに対して、成果指標と取組はその年度の計画に対して）ので、1つの図や目盛りにまとめず、段どうしの差も書かない。区分の内訳の棒は、数えられるくらい少ないもの（20個ほどまで）は1件を1マスにした「マス目の棒」（`StatusBar` の `cells`）にして何個のうち何個かを見せ、多いものと行どうしの割合を比べるもの（5つの将来像のページの基本施策の主な取組、くらしのテーマ・部局の一覧など）はつながった棒にする。マス目の棒にするのは、トップの将来像の行と将来像のページの頭の主要指標（5〜18指標。主な取組のつながった棒と並んでも同じ物差しと読まれないようにもなる）と、施策の行と施策のページの頭の主な取組（1〜14件）。将来像のページの頭と施策の行・施策のページの頭は、枠の棒にせず、指標のマップのマスのような決まった大きさの四角を数だけ並べ（`squares`。将来像のページの頭では成果指標・取組の棒と同じ太さにする。数で長さが変わり、入らなければ折り返す）。将来像のページの頭と施策の行では、四角を押すとその1件の名前（主要指標は基本施策と値も）を指標のマップと同じ吹き出しに出す（`pop`。区分ごとの数のツールチップは出さない）。施策のページの頭では、主な取組の四角と「6/8 件が順調」をまとめて主な取組の節へのリンクにし、成果指標は数ではなく指標の名前と達成率の札を1指標1行で出して（ほとんどの施策で1〜2つ）、名前をその指標のカードへのリンクにする。基本施策とくらしのテーマのページの施策の一覧は、5つの将来像のページの基本施策の箱と同じ2列にする（施策のページの主な取組の一覧も同じ形にし、列の見出しは「進捗状況｜主な取組と活動指標」、行は左の列に進捗状況の札、右に取組の名前とその下の活動指標の名前。行の「詳細」を開くと、取組のページの頭の要点（計画 → 実績の大きな数字と達成割合・決算見込額・所管・4年間の進捗状況・やったこと）を出す。計画と実績の数は詳細にだけ書く）。箱（基本施策のページは施策展開ごと、くらしのテーマのページは将来像ごと）の頭に列の見出し「施策と成果指標｜主な取組」を1回だけ置き、行は左の列に施策の名前と、その下の「成果指標の名前 ▲ 40.7%」（名前のすぐ後ろに達成率の形と数。1指標1行で畳まない）、右の列に主な取組の四角を置く（行には「取組」「順調」の言葉を書かない。スマホの幅では右の列を下に積み、四角の前に「主な取組」と添える）。四角の吹き出しの代わりに、右の列の頭の下向きの矢印（「条件で絞り込む」と同じ印。開くと上向きに回る。取組の数で位置が変わらないよう四角の前に置く）と四角を押すと、行の下に主な取組の名前と進捗状況の一覧を開く（`ShisakuItem` の `toriList`）。トップの頭の3つの段の49指標は、1マスずつだとスマホで細かすぎるので、つながった棒のまま。ものと物差しが1対1に近い段は1つのページにまとめて物差しをものの行に出し（基本施策と主要指標は5つの将来像のページ、活動指標は取組の行。主要指標だけの一覧は作らない）、将来像・基本施策の行は「主要指標 → 主な取組」の順に置き、数も見方も違う段だけ物差しを別のページにする（成果指標をさがす）。
- 状態の言葉（順調・やや遅れ・大幅遅れ など）は県の区分のまま使う。活動指標の数は、どのページでも「計画 10件 → 実績 54件」と書く（「目標」と書くと成果指標の目標値と取り違えるため。100%以上は「計画クリア」）。
- 情報は減らさず「ひとめで → くわしく → 表と原文は畳む（`details`）」の順にする。図には「表で見る」を付ける（例外は、行ごとに区分の内訳の細い棒を並べるもの: トップの将来像の行、5つの将来像のページの基本施策、くらしのテーマの一覧の判定、将来像のページの基本施策の行の主な取組。区分ごとの件数は棒の区間にマウスを乗せる・タップすると出る。トップと将来像のページの頭の3つの段も、すっきり見せるため棒1本と問いに答える割合1つ（主要指標は「前進」、成果指標は「計画値に到達」、取組は「順調」）だけにし、凡例・区分ごとの数・表は置かない。指標のマップも表を置かず、マス1つずつの中身はマスを押すとマスの下（画面に入らなければ上）の吹き出しに出す。区分ごとの数は画面に書かず、マス目の読み上げに入れる）。年度ごとの値の図（取組のページの活動指標、施策のページの成果指標、基本施策のページの主要指標）の「表で見る」は図のすぐ下に置き、図と同じく年度を列にして、PC の幅では列を図の年度にそろえる（スマホの幅では横にすべらせる）。成果指標・主要指標のカードのスタート → いま → ゴールの値は、図が位置を見せるので箱にせず1行にまとめる（活動指標の「計画 → 実績」と同じ）。主要指標のカードには、将来像のページと同じ概要版の達成状況の札（「後退 -6%」）を、将来像のページと同じく名前のすぐ後ろに置く（シェアのボタンの横には置かない。男性・女性のように分けた指標は部分の見出しの横）。基本施策のページの頭の箱（施策のページの頭の判定の箱と同じ地の色の箱）にも、将来像のページの基本施策の行と同じく、概要版の指標ごとに名前と札を並べる。主要指標の県の見通しは、県の見立ての言葉なので、カードの「県」の吹き出しの頭に出す（評価検証報告書の説明があればその下に続ける。年度ごとの見通しはカードの表）。見通しの札は成果指標の見通しと同じ形と文字の札にし、達成状況の札（言葉と数の札）と取り違えないようにする。用語は `Term` で説明し、本文で繰り返さない（`Term` は Tab では止まらない）。
- 節の頭の文は、表示や操作の説明（「棒は〜」「左のハンコは〜」「押すと〜」）にせず、何が載っていて何が読み取れるか（見る人の問いと、ここで分かること・だれが決めたものか）を1文で書く。データの注意書きは図や表の後ろに置く。取組・成果指標・活動指標の年度のつなぎ方（前の年度の名前・載り始めた年度・載らなくなった年度）は、ページの頭やカードに注意書きとして出さず、ページの出典に注釈として書く（年度ごとの有無は4年間のスタンプと、畳んだ「R7の報告に無い〜」で分かる）。取組のページの頭のタイトルの下には、行き先として、前回までの取組・後続の取組（前後の年度の取組で、名前の変更などの可能性があるもの）を、見出しと補足のリンクで並べる（どう選んだかは出典に書く）。複数の施策に載っている同じ取組（県の資料の「再掲」。一度載せたものを載せ直したように読めるので、サイトでは「共通」と言う）は、別の取組に見えないように、頭の番号の後ろに「2施策に共通」と相手の番号（相手の取組のページへのリンク）を出し、相手の施策の名前は出典に書く。取組をさがすの行（施策の後ろ）と目次の取組の行（名前の後ろ）にも「2施策に共通」を出す。トップの主な取組の数（県と同じ延べ件数）には、同じ取組を1件と数えた数を「（重なりを除くと 〇件）」と主な取組の数の下に添える。ただし最新の年度の報告から新しく載った取組は、取組のページの頭（番号の後ろ）と取組の一覧の名前の後ろに「R7から」の札（`YearTag`。薄い青の地に濃い字）を付けて目立たせる。最新の年度の報告に無い取組には、同じ形で灰色がかった青の「R6まで」（最後に載った年度）の札を、取組のページの頭と取組をさがすの行に付ける（施策のページでは「R7の報告に無い取組」に畳んでいるので付けない）。どの取組に付けるかは、取組をさがすの「R7で新しく出た」「R7の報告に無い」と同じ。同じ区分の図を並べるときは、凡例を1回だけ出す。取組のページの活動指標の図は凡例を置かず、図の上に最後の報告の年度の「計画 1件 → 実績 2件」を図と同じ印を付けた文で書く（凡例を兼ねる。ほかの年度の値はツールチップと「表で見る」）。区分の内訳の細い棒を行ごとに並べる所（将来像のページの基本施策の行、くらしのテーマの一覧）は凡例の箱を置かず、行の「順調」「達成率」「判定」を押すと短い説明と区分を出す（`KeyBrief`）。施策の一覧の丸いハンコも凡例の箱を置かず、一覧の上の、一覧から何が分かるかの1行の「県の判定」を押すと区分を出し、ハンコ1つずつの区分はマウスを乗せる・タップすると出す（`JudgeLegend`）。トップの将来像の行と5つの将来像のページの主な取組は、棒を長く・控えめにするため棒だけにする（区分と数は棒の区間にマウスを乗せる・タップすると出る）。5つの将来像のページと将来像のページの主要指標は、名前の後ろに言葉の札で出す（2章）。

## 2. 見た目

- 太い線と硬い影の「ステッカー」を並べるポップな見た目。色はすべて `styles/global.css` のトークンで参照する。はじめは端末の設定に関係なくライトで表示し、ダークはフッターのボタンで選んだとき（`data-theme="dark"`）だけ。
- 年は報告書と同じ和暦で表示する。文章では「令和7年度」と書き、表・図・札・数字の並び（4年間のスタンプ・年度の列など）では「R7」と略す。フッターのボタンで西暦（「2025年度」「2025」）に切り替えられる（選んだら記憶する。`data-era="seireki"`）。西暦にするのは画面の文字と読み上げの名前だけで、外のサイトへのリンクの文字（県の資料の名前・PDF のファイル名）は印字のまま、ページの説明文・SNS のカード・検索エンジンに見せる HTML は和暦のまま（`lib/era.ts`）。
- ステッカーの強さは3段階にする。太い線と大きな影（`.sticker.lift`）はページの頭とトップのヒーローだけ。並ぶカード・図・絞り込みは `.sticker`。ステッカーの中の箱は線も影も付けず地の色だけ（`.inset`）にし、中の吹き出しやステッカーにも影を付けない。
- 状態（順調〜大幅遅れ、判定 A〜G）は色に加えて、形（● ◆ ▲ ■、判定 E・F は ▼ と斜線）と文字で出す。形は `lib/icons.ts` を通して出す（`Icon`・`Chip`）。地との差が 3:1 未満の状態の色（ライトの黄・灰、ダークの赤・灰）は、形と内訳の棒の区間（指標のマップのマスも。マスの黄・灰は付けない）に濃い（ダークでは明るい）縁を付ける（`styles/global.css` の `--*-edge`）。
  - 例外: 指標のマップのマスは色だけの四角にする（約2,000個あり、形を入れると細かすぎる）。凡例にマスと同じ色の四角と形・文字を並べ、押すと吹き出しに区分の言葉を出す。
  - 例外: 基本施策・くらしのテーマのページの施策の行で開く取組の一覧は、スマホの幅では取組の名前を広く取るため、進捗状況を色と形の印だけにする（文字は読み上げに残し、印をタップすると出す）。
  - 例外: 5つの将来像のページと将来像のページ・基本施策のページの主要指標の札（指標のマップの主要指標の凡例と中身の札も）は、形を付けず、県の概要版の区分の言葉と数（「後退 -6%」「前進 44%」）を区分の色の札に書く（`components/ShuyouTags.astro`）。形は取組の進捗状況の並びから来ていて、主要指標では「前進（60%未満）」が「やや遅れ」と同じ▲になり、前に進んでいるのに遅れに見えるため。言葉で状態が読めるので、色だけには頼らない。
- 施策と主な取組を見た目で取り違えないようにする。丸いハンコは施策の判定（A〜G）だけに使い、取組の進捗状況は横長の札と4年分のスタンプで出す。
- 将来像の色（`--sz-1`〜`--sz-5`。[基本計画のパンフレット](https://www.pref.okinawa.jp/_res/projects/default_project/_page_/001/014/250/shin21seikivision-kihonnkeikaku-pamphlet.pdf)の色）は番号の印と見出しの帯だけに使い、状態の色とは混ぜない。
- 日本語のウェブフォントは読み込まない。数字だけ丸い英字フォント Fredoka の部分集合（`src/fonts/`。SIL OFL）を使う。
- 見出しにも文章にも `text-wrap: balance`・`text-wrap: pretty` は使わない。行の長さをそろえるので、どの行も早めに折り返されて右が空く（2〜3行の見出しが短い行の積み重ねになる。iOS の Safari は pretty でも段落の全部の行をそろえる）。見出しとページの頭の説明（`.lead`）は `word-break: auto-phrase` で文節の区切りで折り返す（対応していないブラウザでは行の端で折り返す）。
- 印刷では、ナビ・年の書き方と配色のボタン・目次・絞り込み・シェアを出さず、タイトル（非公式の印）とフッターの作り手の1行は残す。畳んだ内容と「さらに表示」の残りは開いて出し、図は紙の幅で描き直す。ダークを選んでいても白い地のライトで印刷し、状態の色はそのまま出す（`@media print` と `scripts/print.ts`）。

## 3. 一覧・番号・リンク

- 一覧はふつう、1つの箱の中に細い線で区切った行で並べる（`.row-list`）。1件は2〜3行に収め、一覧の見出しにあること（将来像・基本施策）は行に書かない。1件の中身が多く、行にすると右が空くもの（将来像のページの基本施策）は、1件ずつのカードにして PC では2列に並べる。
- 絞り込み（`list-filter.ts`）の条件は URL のクエリに残し、一覧の上に × で外せる条件を並べる。キーワード以外の条件は `FilterMore` で畳む。指標のマップの絞り込みは、条件に合わないマスを隠さずに薄くする（全体の中のどこにあるかを見せるため）。長い一覧は「さらに表示（残り N件）」で残りを全部出す（`show-more.ts`）。
- 報告書の番号（`1-(1)-ア-①` など）は名前より目立たせず、カードの隅や名前の後ろに小さく薄い字で置く（`.code-no`）。施策・主な取組・基本施策・成果指標・観光ロードマップの施策展開のページの頭は、1行目の左に何のページか（区分）をやや大きく、その後ろに番号を小さく置き、くらしのテーマは同じ行の右端に置く（`components/HeadKind.astro`。「テーマ」の文字は付けず、ピンクの札にマウスを乗せると、このサイト独自の分類だと出す）。主な取組は、施策の番号の後ろに施策の中の報告書の番号を付ける（`1-(1)-ア-①-2`）。ページの題名は名前だけにする。番号でも検索できるようにする。例外は計画の目次（`/mokuji/`）とページの階層（4章）で、通しの番号は出さず、その階層の中の番号（基本施策の (2)・施策展開のイ・施策の①・主な取組は施策の中の報告書の番号 1, 2, …）を名前の頭に置く（上の階層は木の形で分かるため）。計画の目次の件数は、閉じている行にだけすぐ下に並ぶものの数（「成果指標 2・取組 6」）を名前の後ろに出す。主要指標・成果指標・活動指標は「指標」の札を付けた名前だけにし（主要指標・成果指標は、PC の幅では基本施策・施策の名前の横に補足のリンクとして並べ、スマホでは開いた中の行にする。活動指標は取組の名前の右）、値や達成率は出さない（目次は計画の形を見るページで、良い・悪いの一覧にしない）。どの指標を出すかは、頭の「指標」のボタンで開くチェックボックスで選ぶ（はじめは主要指標と成果指標だけ）。
- サイトの中のリンクは3種類に分ける。名前のリンク（一覧の行・カードの見出し・図の行の名前）は `.name-link`（黒の太字に薄い下線）、補足の部局・施策の名前は `.sub-link`（灰色に薄い下線）、文章の中のリンクと行き先を示すリンクは青に下線。名前と補足のリンクは、カーソルを乗せても青にせず下線を黒く太くする。
- 沖縄県PDCAについて・データについて・このサイトについての節の見出しは、見出しの文字をその節の # へのリンクにし（`components/SecHead.astro`）、節を指した URL を共有できるようにする。見出しは青や下線にせず、後ろの薄い「#」はカーソルを乗せたとき・フォーカスしたとき・押したときだけ出す（読み物の見出しに印を並べないため）。

## 4. ヘッダー・目次・ページの階層

- ヘッダーのナビはサブメニューを使わず項目を並べる。トップはヘッダーのタイトルから戻れるのでナビに置かず、くらしのテーマを先頭にする。その後ろは計画の3つの段（1章）を上から、段ごとにものと物差しを隣にして並べ（将来像・主要指標｜施策・成果指標｜取組）、部局・予算、3つの段をまとめて見る計画の目次・指標のマップ、沖縄県PDCAについて・このサイトについてと続ける（データについては、このサイトについての中のページとしてナビに置かず、その項目をいまの場所にする）。まとまりのあいだには細い区切りの線を置く。タイトルの横に、最新の対象年度の版（「令和7年度版」）を木の板で出す。スマホでは、ロゴの右に「タイトル＋版」と「（非公式）by …」の2行を収め、その下にナビを置く。
- 1つのものを見せるページには、頭の札のすぐ後にページ内の目次（`Toc`）を置いて上に固定する。貼り付いたら何のページかを1行で出し、本文がずれないよう本文に重ねる。
- パンくずの代わりに、ページの頭の上にページの階層（`Hierarchy`）を置き、いまのページが計画のどこに入っているかを見せる。いまのページの上の段（計画の体系なら 将来像 → 基本施策 → 施策展開 → 施策。`lib/data.ts` の `planPath`・`planParents`）を、目次のように1段ずつ右へ下げて線でつなぐ。いまのページと基本計画の名前は入れず、最後の段から線を伸ばして、すぐ下のページの頭のステッカーにつなぐ（取組のページは、入っている施策の段からつながる。親の施策の札は置かない）。上の階層の無いページ（将来像のページ・ナビから入る一覧）と、くらしのテーマ・部局のページ、観光ロードマップのトップには置かない（観光ロードマップの中のページも、個別計画の段は入れない）。施策・基本施策・観光ロードマップの施策展開のページの頭には、階層と同じこと（「施策展開「〇〇」の施策」など）を書かない。
  - 段は番号の下から次の段の頭へ木の形の線でつなぐ（押せるボタンに見える印は付けない）。段の番号（「(1)」「ア」「①」）は名前の前に薄い字で置く。将来像も色の帯にせず、ほかの段と同じ形の行にして、番号を将来像の色の丸（`Sz`）にする。将来像と計画の段（基本施策・施策）は太字、まとまり（施策展開・一覧のページ）は細字にする。ページの無い施策展開はリンクにしない。
  - スマホの幅では、ページの階層のあるページをリンクから開くと、ページの頭が画面の上にくる位置から始める（ヘッダーと階層でページの頭が画面の半分近くまで下がるため。階層とナビは上へ戻ると見える）。戻る・進む・再読み込みと、`#` の付いた URL ではブラウザの位置のまま。PC の幅ではページの頭が最初から見えるので動かさない。
  - 名前は縮めずに折り返す（スマホでも）。PC では箱を中身の幅にする。

## 5. 県の計画とは別のもの

- くらしのテーマは**このサイト独自の分類**で、県の計画の分類ではない。画面では必ずそうと分かるように出す（「このサイト独自の分類」の印・ピンクのラベル `ThemeTags`）。どの施策もいずれかのテーマに入るように `themes.json` を保つ（`make test` で確かめる）。
- 個別計画（観光ロードマップ）と一括交付金の事後評価は、沖縄県PDCAとは別の計画・評価。施策をさがす・取組をさがすの一覧と件数には混ぜず、札の色で見分ける（個別計画は淡い紫の `.plan-tag`、一括交付金は砂色の `.ik-tag`）。ただし、施策のページの一括交付金の節のカードには札を付けない（節の見出しで分かり、どのカードにも同じ札が並ぶため）。一括交付金の事業は、名前が同じでも主な取組・部局票の予算事業と結び付けない。
- 個別計画はヘッダーのナビと5つの将来像のページには置かず、くらしのテーマ・関係する施策と取組のページ・フッターから入る。
- サイトの説明は、誰の話かで3ページに分ける。県が決めて公表していること（仕組み・計画の階層・達成率の物差し・用語）は沖縄県PDCAについて（`/pdca/`）、このサイトが県の資料をどう読んで数えたか（出典・作り方・数え方・くらしのテーマの分け方・公表値とのずれなどの注意点・沖縄県PDCA以外の資料の注意点）はデータについて（`/data/`）、このサイトそのもの（なりたち・シビックテックと作り手の Code for Okinawa・技術・デザイン・アクセシビリティ・運営と問い合わせ）はこのサイトについて（`/about/`）。県の説明とこのサイトの読み方を同じページに混ぜない。用語（沖縄県PDCAについての一覧と、点線の言葉の吹き出し。`lib/terms.ts`）も県の言葉だけにし、このサイト自身の言葉（くらしのテーマ）は一覧に並べず、吹き出しから説明の章へつなぐ（`OWN_TERMS`）。データについては、数字を読むのに要ることだけを短く書き、例外の一覧や件数の内訳は [data.md](data.md)・[issues.md](issues.md) に任せる。

## 6. 意見・シェア・いいね

- 施策・基本施策・取組・部局・将来像・くらしのテーマのページは、終わり（出典の前）にいいねとシェアの枠（`ShareBox`）を置く（ページの頭にはシェアのボタンを置かない）。シェアの SNS のアイコンの最後に、ページのリンクをコピーするボタン（リンクの形。押すと2秒チェックの印になる）を置く。スマホの幅では、いいねとシェアが1行に並ぶよう、ハートを 48px、シェアの丸を 38px にする。枠の言葉は、施策への賛成ではなくページへのいいねと読めるよう「ページが役に立ったら」にする。
- 指標（主要指標・成果指標・活動指標）は、指標だけのページを置かず、カードの右上の「シェア」のボタンで1つずつシェアできるようにする（`components/ShareMenu.astro`）。押すと、カードの右上から小さな枠を開き、「この〇〇をシェア」の見出し・SNS のアイコン・リンクの欄と「リンクをコピー」を並べる。シェアするのは指標のシェア用のページの URL で、SNS には指標の名前と道のり（活動指標は計画と実績）の画像が出て、開いた人はそのカードに着く（[site.md](site.md) の4章）。ほかの場所を押す・Esc で閉じ、1つ開くとほかは閉じる。ボタンはカードの中なので影を付けず、達成率の札と並べる。
- **いいねの件数は画面に出さない**（よく押された施策の順という物差しができ、1章の「同じ重み」とぶつかるため）。コメントの欄も置かない。
- SNS に書いても県には届かないことは `/iken/` で伝える。ハッシュタグ（`lib/iken.ts` の `HASHTAG`）は公開の場の X・Threads・Bluesky にだけ付ける。

サイトの名前は「おきなわ、みらい、いま」（縮めて「みらいま」）。名前・略称・説明は `lib/links.ts` の `SITE`、作り手（Code for Okinawa のプロジェクトとして saboyutaka が管理）は `PROJECT`、ハッシュタグ `#okinawa_miraima` は `lib/iken.ts` の `HASHTAG` に1か所で決め、画面の文字もここから出す。

## 8. 動き

サイトを楽しく、分かりやすくするために動きを付ける。ただし、表示が遅くなる・ガタつく・読む手間が増える動きは付けない。

- **意味のある動きだけ。** 付けるのは、押した・変わったの手ごたえ、図を読む順（スタート → いま → ゴール）、どこからどこへ移ったか、の3つ。飾りだけの動き、ずっと動き続けるもの（ふわふわ浮く・点滅・ループ）、数字のカウントアップ、スクロールに合わせて要素を出す動き、パララックスは使わない。
- **1回だけ短く。** ボタンや吹き出しは0.1〜0.25秒、図は描き終わるまで0.8秒ほど。
- **ページを移るときは重ねて切り替えない**（`@view-transition` は使わない）。ページの階層の段の数がページごとに違い、前と次のページの頭が上下にずれて二重に見え、がたつくため。
- **見た目だけを動かす。** transform・scale・opacity・clip-path・SVG の線の描き方だけを動かし、幅・高さ・位置などレイアウトにかかわるものは動かさない。
- **ふだんの見た目は動き終わった形。** キーフレームには始まりの形だけを書く。端末で動きを減らす設定（`prefers-reduced-motion: reduce`）・印刷・対応していないブラウザでは、はじめから動き終わった形で見える。`make shot` も動きを減らす設定で撮る。
- **状態の区分はどれも同じ動き。** 遅れだけを揺らす・順調だけを光らせる、はしない（1章）。一覧の行のように数の多いものは動かさない。
- 動きの見た目は `styles/global.css` の「動き」に1か所でまとめ、スクリプトから動かすものは `scripts/motion.ts` を使う。外のライブラリは足さない。

## 9. アクセシビリティ

目の見え方や使う道具（読み上げソフト・キーボードだけの操作・動きを減らす設定）にかかわらず、同じ内容に届くようにする。状態の色・形・文字は2章、図の「表で見る」と `Term` は1章、動きは8章、外部リンクの読み上げは [site.md](site.md) にあり、ここでは繰り返さない。

- **値は必ず文字でも出す。** 図・色・ツールチップにしか無い値を作らない。図の値は「表で見る」・行の文・`aria-label` のどれかで読めるようにする。マウスを乗せる・タップすると出るツールチップ（`scripts/tip.ts`）は補助で、読み上げソフトには出さない。
- **図は1つの画像として読み上げる。** 図の枠に `role="img"` と値をまとめた `aria-label` を付け、中の SVG は読ませない。積み上げの横棒（`StatusBar`）は区間ごとに Tab で止めない。年度ごとの値の図（`TrendChart`・`SeikaChart`・`KatsudouChart`）は Tab で止まり、← → で年度を移って値を出し、Esc で消す（`scripts/charts.ts`）。指標のマップのマス目も Tab で1回だけ止まり、矢印キーでマスを移って、その指標の中身を吹き出し（`aria-live`）に出し、Enter でその指標のページへ移る（`scripts/indicator-map.ts`）。止まっただけでは吹き出しを開かず、矢印キーで移れること・Enter で開けることを小さく出し、フォーカスがマス目・吹き出し・絞り込みの外へ出たら閉じる。キーで移れること・開けることは `aria-label` の終わりに書く。押せる四角（将来像のページの頭の主要指標。`StatusBar` の `pop` の `keys`）も同じで、Tab で1回止まり、← → で1件ずつ移って中身を吹き出しに出し、Enter でそのページへ移る（`scripts/cell-pop.ts`）。施策の行の四角は押せば中身を出すが Tab では止めない（行ごとに止まると一覧の Tab が倍になり、同じ取組は名前のリンクの先の施策のページにある）。基本施策・くらしのテーマのページの施策の行の、取組の一覧を開くボタン（`summary`）は Tab で止まる（開いた一覧に取組のページへのリンクがあるため）。
- **同じことを2回読ませない。** 画面に見えている文字と同じ内容（目次が貼り付いたときの1行 `Toc`、すぐ横に「将来像N」とある番号の印 `Sz sr={false}`、棒の読み上げに入っている数 `KeyNum`）や、見た目だけの印は `aria-hidden` にする。
- **見た目で分かることは読み上げ用の文で補う。** 行の基準値・実績値・目標値、スタンプの年度、表の `caption`、アイコンだけのシェアの名前などは `.sr-only` の文にする。スマホで隠す文字（「いいね」の文字）は読み上げには残す。ページの階層の段の名前（「基本施策」「施策展開」など）は、番号だけでは何の段か分からないので読み上げ用の文で足す。マウスを乗せると出る区分の説明（`title`。「計画の90%以上」など）は読み上げソフトがふつう読まないので、凡例では `.sr-only` でも出す（`Chip` の `readTitle`）。行ごとの札は毎行読まれてうるさいので付けない。
- **キーボードで使える。** 全ページの先頭に「本文へスキップ」（`layouts/Base.astro`。フォーカスしたときだけ見える）を置く。フォーカスは `:focus-visible` の太い枠（`--pop` の 3px）で示し、消さない。貼り付いた目次のあるページは、フォーカスした要素が目次の下に隠れないよう上を空ける（`scroll-padding-top`）。押したボタンが消えるとき（絞り込みの札・「さらに表示」）は、フォーカスを続きの場所へ移す。横にすべらせる表は、入りきらないときだけ Tab で止めて ← → で送れるようにする（`scripts/table-scroll.ts`）。計画の目次の木は Tab で1回だけ止め、矢印キーで行を移って開け閉めし（指標には止めない）、Enter で名前のページを開く（WAI-ARIA の tree の形。`scripts/tree.ts`）。止まったときは、指標のマップと同じく矢印キーで動かせることを小さく出す。押せるボタン型の選択肢（`.fchip`）は中身を本物の radio・checkbox にして、キーボードと読み上げの動きをそのまま使う。吹き出し（用語・いいねのお礼）とツールチップは Esc で閉じ、用語の吹き出しは閉じたら押したボタンにフォーカスを戻す。
- **状態の変化は属性で伝える。** いまのページ・節は `aria-current`（ナビは `page`、目次は `location`）、開け閉めは `aria-expanded`、いいねは `aria-pressed`。画面にだけ出る知らせ（いいねのお礼・配色を切り替えたこと）は `role="status"` の文、件数が変わる一覧（取組をさがす）は `aria-live` で伝える。
- 文書の言語は `lang="ja"`。SNS のカードの画像には説明の文（`og:image:alt`）を付ける。
- **色のコントラストの基準（WCAG など）と、ウェブアクセシビリティの規格（JIS X 8341-3 など）に沿う。** このサイトについてのページ（`/about/#accessibility`）でも、沿っていると書いている。色やページの作りを変えるときは、これを崩さない。
