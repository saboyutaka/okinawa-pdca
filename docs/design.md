# デザインの決まり

ユーザーと決めた、サイトの見た目と見せ方の決まり。画面を変える・足すときは先に読む。要点は CLAUDE.md の「デザインの大原則」にもある。

## 1. 方針

- **県を批判するためのサイトではなく、状況を公平に確かめるためのもの。** 順調なもの・遅れているもののどちらかだけを選んで目立たせない（ヒーローや節の頭に遅れの件数を大きく並べる・悪い順に並べる・良いものだけに絞ったリンクを置く、はしない）。全体の内訳を同じ重みで見せ、遅れている取組・判定が下がった施策・後退した指標などは、一覧の絞り込み（`?pat=delay3`・`?trend=down` など）で見たい人が見られるようにする。前の年度からの変化を出すときは、良くなったものと悪くなったものを対にする。状態の言葉（順調・やや遅れ・大幅遅れ など）は県の区分のまま使う。
- 情報は減らさず「ひとめで → くわしく → 表と原文は畳む（`details`）」の順にする。図には必ず「表で見る」を付ける。棒の区間ごとにタブで止めない。用語は `Term` で説明を出す。
- 節の頭の説明は、その図や表を読むのに要る1文だけにする。用語の意味は `Term` に任せて本文で繰り返さない。データの注意書き（重複・出典の事情など）は図や表の後ろに置く。同じ区分の図をいくつも並べるページでは、凡例はページに1回だけ出す（`StatusChart` に `legend={false}`）。

## 2. 見た目の基本

- 太い線と硬い影の「ステッカー」を並べるポップな見た目。色はすべて `styles/global.css` のトークンで参照する。はじめは端末の設定に関係なくライトで表示し、ダークはヘッダーのボタンで選んだとき（`data-theme="dark"`）だけ。
- ステッカーの強さは3段階にして、全部を同じ強さにしない（どこから見ればいいか分からなくなるため）。太い線と大きな影（`.sticker.lift`）はページの頭とトップのヒーローだけ。並ぶカード・図・絞り込みは `.sticker`（細めの線と小さな影）。ステッカーの中の箱は線も影も付けず地の色だけ（`.inset`）にし、中の吹き出しやステッカーにも影を付けない。
- 状態（順調〜大幅遅れ、判定 A〜G）は青信号系の色に加えて、形（● ◆ ▲ ■、判定 E・F は ▼ と斜線）と文字で出す。色だけで伝えない。形は `lib/icons.ts` を通して出す（`Icon`・`Chip`）。
- 将来像の色は[基本計画のパンフレット](https://www.pref.okinawa.jp/_res/projects/default_project/_page_/001/014/250/shin21seikivision-kihonnkeikaku-pamphlet.pdf)の色（1 緑・2 青・3 橙・4 ピンク・5 青緑。`--sz-1`〜`--sz-5`）。番号の印と見出しの帯だけに使い、状態の色（棒・印）とは混ぜない。
- 日本語のウェブフォントは読み込まない。数字だけ丸い英字フォント Fredoka の部分集合（`src/fonts/`。ビルドで `/_astro/` に書き出す。ライセンスは `public/fonts/Fredoka-OFL.txt`、SIL OFL）を使う。

- 印刷（勉強会や会議の資料に）は、ナビ・配色のボタン・目次・絞り込み・シェアを出さず、タイトル（非公式の印）とフッターの出典の文は残す。畳んだ内容（表で見る・前の年度のふりかえりなど）と「さらに表示」の残りは開いて出し（紙では押せないため）、図は紙の幅で描き直す。地の色は白、ダークを選んでいてもライトで印刷する。状態の色はそのまま印刷する（形と文字でも出しているので白黒でも読める）。`styles/global.css` の `@media print` と `scripts/print.ts`。

## 3. 施策と主な取組を見分ける

- 施策と主な取組を見た目で取り違えないようにする。大きな丸いハンコは施策の判定（A〜G）だけに使い（一覧の行と親の施策の札では小さな丸いハンコ `.jstamp`）、取組の進捗状況は横長の札と線でつないだ4年分のスタンプで出す。取組のページと成果指標のページの頭は、親の施策の札（`components/ParentShisaku.astro`）の下にカギ形の線でぶら下げる（`.hang`）。

## 4. 一覧

- 一覧（施策・成果指標・遅れている取組・取組の検索）は1件ずつをステッカーにせず、1つの箱の中に細い線で区切った行で並べる（`.row-list`）。1件は2〜3行に収め、一覧の見出しにあること（将来像・基本施策）は行に書かない。部局・くらしのテーマは絞り込み（`data-*`）と詳しいページに任せる。施策の行は `components/ShisakuItem.astro`（判定はハンコだけで出し、判定の言い方や前の年度の判定は行に書かない。A〜G の意味は一覧の上に `components/JudgeLegend.astro` で1回だけ出す。年度ごとの判定は施策のページの「4年間の判定」に任せる）、成果指標の行は `components/SeikaRow.astro`（左に名前と施策の2行、右に達成率の札と施策ページの図の縮小版 `SeikaSpark`。札は施策の行の成果指標の札と同じ数字だけの形（`lib/data.ts` の `rateText`・`rateTone`）。図の横は R4〜R9 の6枠でどの行もそろえ、地の色が前期。凡例は一覧の上に `SeikaKey mini` で1回だけ。見通しは達成率の区分とほぼ重なるので行に出さず絞り込みに任せ、基準値・実績値・目標値は図に任せて読み上げ用の文にだけ残す）、取組の行は `.t-row`（styles/global.css。取組をさがすはブラウザで同じ形を描く）を使う（部局のページの一覧も同じ）。
- キーワードは「子ども」「子供」「こども」・「障害」「障がい」のどの書き方でも同じように当たる（`lib/search.ts`。施策をさがすなどの `list-filter.ts` と取組をさがすで同じ比べ方）。取組をさがすのキーワードは、名前などのほかに最新の報告の「やったこと」（総括報告書の取組の概要）も探す（市町村の名前や「不登校」のような言葉は、ここに書かれていることが多いため）。やったことにだけ当たった行には「R7にやったこと: …」を1行足し、なぜ出たかが分かるようにする。
- 絞り込み（`list-filter.ts`）の条件は URL のクエリに残し（# の行き先は消さない）、一覧の上に「× で外せる」条件を並べる。キーワード以外の条件は `FilterMore` で畳み（初めは閉じる。最初の画面に一覧が入るように）、初めの選択から変えた条件の数をボタンに出す（取組の検索も同じ）。
- 長い一覧は「さらに表示（残り N件）」で残りを全部出す（`show-more.ts`）。最新の年度の県のふりかえり・活動と検証は途中で切らずに全部出す。

## 5. カードと図

- 施策ページの成果指標のカード（`components/SeikaCard.astro`）は「計画値に届いたか（達成率の印と1文）→ スタート → いま → ゴール（基準値・実績値と計画値・目標値と県の見通しを時間の順に。数字はここに1回だけ）→ 道のりの図 → 県による説明（「県」の印の吹き出しで畳まずに出す）→ 表（畳む）」の順にする。見出しの名前と、カードの終わりの「この指標だけのページを見る」は成果指標のページへのリンク。①計画値に届いたか〜ゴール（`SeikaGoal`）・道のりの図と注意（`SeikaRoute`）・県による説明（`SeikaSays`）・表（`SeikaTable`）は、成果指標のページと同じ部品を使う。図（`charts.ts` の `seika`）は横が報告年度で、スタート（基準値）から点線の計画の道すじをたどってゴール（目標値）へ向かう形に、青い点の実績値と「いまここ」を重ねる（前は道のりの棒と推移の図の2つがあり、同じ数字を何度も並べていた）。凡例は節の頭に1回だけ。
- 主要指標の移り変わりの図（トップの「主要指標で見る、くらしの大きな数字」`components/ShuyouTrendTop.astro` と、将来像ページの「主要指標の移り変わり」）は、県の概要版の49指標（1指標1行。[data.md](data.md) の 4.5）を、1指標1行（`components/ShuyouTrendList.astro`。名前（基本施策ページのそのカードへのリンク）・いまの値・報告年度ごとの実績値の小さな折れ線・達成率）で見せる。折れ線は `SeikaSpark`（主要指標の一覧と同じく計画の道すじは引かずゴールの丸だけ）で、行を低くするため平たくする（`h={26}`）。スマホでも図は右に置き、左にいまの値と達成率を重ねる。値は `lib/data.ts` の `getShuyouStatus` の `series`（最新の年度は概要版、それより前は付属資料）。並びは概要版の表の順（良い・悪いで並べ替えない・どれかを選んで大きく出さない）。トップは将来像の見出しの下に同じ行を並べ、将来像ごとに最初の5件より後は「さらに表示」（表の順で切るだけで、選ばない）。下に区分ごとの数を同じ重みで1行（前進（うち目標値に到達）・横ばい・後退・比べられない）と「表で見る」。スタート・ゴールの値と、いまの値が何年の値かは行に文で書かず（ごちゃつくため。基本施策のページのカードにもある）、図の点（各年度の実績値・スタートの基準値・ゴールの目標値）にマウスを乗せる・押すとツールチップで出す（`SeikaSpark` の `.sp-hit`。点より大きい透明な円に `data-tip-*` を付ける。主要指標の図だけで、行の多い成果指標の一覧には付けない。読み上げ用の文には値を残す）。主要指標の小さな図は、計画の道すじが無いので R4〜R9 の全体に地を敷き前期の地を少し濃くして（`styles/global.css` の `.spark-goal`）、白い地の行でも図がひとまとまりに見え、ゴールの丸が図の中に入るようにする（主要指標の一覧の行も同じ）。凡例は図の上に1回だけ（`SeikaKey mini plan={false} goal`。スタートの基準値の点も出す）。値は概要版のまま出し、統計の基準改定で試算し直したもの（`revised`）には「※」を付けて説明する。主要指標の達成率は成果指標の達成率（その年度の計画値に対する割合）と意味が違うので、`Term` は「主要指標の達成率」を使う。（前に試した、達成率の位置に点を置く「道のり」の図と、トップに図の箱を並べる形は使わない。2026-10-12）
- 主要指標の一覧（`/shihyou/shuyou/`。成果指標をさがすの頭と基本施策ページの主要指標の節から入る）は、平均寿命や観光収入のような大きな数字を基本施策のページをめぐらずに見るためのもの。将来像の見出しの下に報告書の順で並べ（良い・悪いで並べ替えない）、最新の報告の指標だけを出す（R6までの指標は基本施策のページ）。行は `components/ShuyouRow.astro` で、成果指標の一覧の行と同じ形（左に名前と基本施策、右に札と小さな図 `SeikaSpark`）。付属資料の主要指標一覧には達成率がないので札は県の見通しにし、図には計画の道すじを引かずゴールの丸だけを置く（凡例は `SeikaKey mini plan={false} goal`）。男性・女性のように分けた部分は1行ずつにし、分けられず見通しが2つ以上ある指標は札を部分の名前つきで縦に並べる。名前は基本施策ページのそのカード（`#shuyou-N`。`lib/data.ts` の `shuyouAnchor`）へのリンク。指標が少ないので絞り込みは置かない。
- 基本施策ページの主要指標のカード（`components/ShuyouCard.astro`）も同じ並びと図にする。付属資料の主要指標一覧には達成率と年度ごとの計画値がないので、頭の1行は県の見通しにし、図には計画の道すじを引かずにゴールの丸だけを置く。主要指標は報告書の文字のまま持っているので、図に置く数は `lib/data.ts` の `shuyouRows` で読み取る（「3兆2,885億円」などの位も読む。画面に出す値は報告書の文字のまま）。男性・女性のように1つの欄に値が並ぶ指標は、見通しの欄の名前で分けて、部分ごとに図を出す。目標値が文の指標（「可能な限り減少させる」など）は、ゴールの丸を置かずにスタートと実績値だけを描く。分けられない・数で読めない指標は図を出さず、値を文のまま並べる。
- 施策ページの成果指標でも、目標値が文の指標（「跡地における〜を目指す」など）は、基準値・実績値を同じように読んで（`lib/data.ts` の `textGoalChartRow`）、スタートと実績値だけの図を出す（一覧の行の小さな図 `SeikaSpark` も同じ）。目標が「〜との差の縮小」の指標は、値の図では目標に近づいたか分からないので図を出さない。
- 活動指標の数は、どのページでも「計画 10件 → 実績 54件」と書く（総括報告書の欄の名前は「目標」だが、成果指標の目標値（R9のゴール）と取り違えないよう、進捗状況の説明（その年度の計画に対してどこまで進んだか）と同じ「計画」にそろえる。100%以上は「計画クリア」）。
- 取組ページの活動指標は、成果指標と同じ形の図（`components/KatsudouChart.astro`、`charts.ts` の `katsudou`）で、年度ごとの計画（点線でつないだ白い丸）と実績（青い点）を並べる（前は年度ごとのカードと年度別計画の矢印の並びで、同じ数字を何度も出していた）。最新の報告にある取組は、部局票の年度別計画からこの先の年度（R8・R9）の計画も白い丸で置く。活動の量なので縦の目盛りは0から、値は「10件（20件）」のかっこの前のその年度の数で描く（かっこの中は累計や内訳）。実績が計画と同じ高さの年度は、計画の丸を実績の点の外側の輪にする。活動指標が途中で変わった取組は、活動指標ごとにカードを分ける（新しいものが先。`lib/data.ts` の `activityRuns`）。数で読めない活動指標（「方針検討」など）は図を出さず、年度ごとの表を開いて出す。進捗状況は頭の4年分のスタンプにあるので、図の中には書かずツールチップと表に出す。
- 「このサイトについて」（`/about/`）の計画の階層の図（`components/PlanMap.astro`）は、将来像 → 基本施策 → 施策 → 主な取組の幹に、それぞれの指標（主要指標・成果指標・活動指標）を実線で、くらしのテーマを点線のかっこでつなぐ（PC は「指標 ─ 階層 ┄ テーマ」の3列、スマホは幹に指標をぶら下げる1列）。方眼ノートに手で描いたような見た目にし、枠と線だけを SVG のフィルターで揺らす（文字は揺らさない）。この図の箱は例外として、`.inset` にせず線で囲む。くらしのテーマはテープで貼った付箋にする。数は最新の年度をデータから数える。文字のまま読めるように SVG にせず HTML の箱と線で組むので、「表で見る」は付けない。

## 6. 番号とリンク

- 報告書の施策の番号（`1-(1)-ア-①`・基本施策の `1-(1)`）は名前より目立たせない。ページの頭のステッカーと一覧のカードでは右上の隅に、カードの無い一覧のリンクや見出しでは名前の後ろに、小さく薄い字で置く（`styles/global.css` の `.code-no`・`.code-corner`・`.name-row`）。パンくずとページの題名は名前だけにする（例外は、同じ取組が複数の施策に載っているときの取組のページの `<title>`。施策ごとのページの題名が同じにならないように、後ろに施策の番号を足す。[site.md](site.md) の6章）。施策・基本施策・取組のページの最後の「出典」の節に「県の報告書での番号」として説明を置く（報告書の PDF をこの番号で探せる）。検索の文字（`data-text`・`/torikumi/data.json`）にも番号を入れ、番号でも探せるようにする。
- サイトの中のリンクは3種類に分ける。名前のリンク（一覧の行の名前・カードの見出し・図の行の名前）は `.name-link`（黒の角ゴシックの太字に薄い下線。見出しの丸ゴシックは太さが1つしかなく太字にならないので使わない）。補足の行の部局・施策の名前は `.sub-link`（灰色に薄い下線）。文章の中のリンクと「すべて見る」のような行き先を示すリンクは青に下線のまま（黒の太字にすると強調と見分けがつかないため）。名前のリンクと補足のリンクは、カーソルを乗せても青にせず、下線を黒く太くして反応させる（色が変わると別の種類の文字に見え、一覧ではちらつくため）。

## 7. ヘッダー・ナビ・パンくず

- ヘッダーのナビはサブメニューを使わず項目を並べる（開くと本文がずれるため）。トップにナビと重複する「くわしく見る」は置かない。スマホのヘッダーは「タイトル＋配色のボタン（その下に小さく（非公式）by Code for Okinawa）」と「ナビ」の2段に収める。ナビが横にはみ出すときは、ページを移ってもナビの横の位置を変えない（跳ばないように）。いまいるページの項目が見えないときだけ、その項目を真ん中に寄せる。
- 公開前（ステルス）のあいだは、全ページのヘッダーの上に「ベータ版」の帯を出し、沖縄県への問い合わせが済むまでは検索エンジンに載せていないことを書く（`lib/links.ts` の `STEALTH`。検索エンジンに載せない設定と同じ切り替えで、公開するときに一緒に消す）。SNS のシェアボタン（9章）は、このあいだも出す（前は SNS への投稿を控えてもらい、ボタンを隠していた）。状態の色と取り違えないよう、地は文字の色にして反転させる。印刷にも残す。
- パンくずは計画の体系「将来像N › 基本施策 › 施策」「将来像N › 施策 › 取組」（`components/Crumbs.astro`）。トップはヘッダーのタイトルから戻れるので入れず、上の階層の無いページ（ナビから入る一覧・予算と財源・このサイトについてなど）にはパンくずを置かない。スマホでは、すぐ下の見出しと同じいまのページの名前を見せず、折り返さずに1行に並べて、入りきらない名前は「…」で縮める（将来像の印の付いたリンクは縮めない）。

## 8. 県の計画とは別の分類・別の計画・別の評価

- くらしのテーマは**このサイト独自の分類**で、県の計画の分類ではない。画面では必ずそうと分かるように出す（「このサイト独自の分類」の印・ピンクのラベル `ThemeTags`）。どの施策もいずれかのテーマに入るように `themes.json` を保つ（入らない施策があるとビルドで警告し、`make test` で落ちる）。主な取組・成果指標は、施策のテーマに加えて名前に当たるテーマにも入る。
- 個別計画（観光ロードマップ）は県の基本計画とは別の計画。県民は計画の名前ではなく分野から探すので、計画が1つのうちはヘッダーのナビに置かず、くらしのテーマ（観光ロードマップはテーマ「観光」）の要約の枠（`components/RmSummary.astro`。主な取組の進捗状況と、成果指標の前進・横ばい・後退の内訳の数だけを出す）・関係する施策と取組のページ・フッターから入る。将来像の一覧の中には入れない。観光ロードマップのページは、くらしのテーマ・将来像のページと同じく、頭の札 → 基本施策と施策展開 → 成果指標 → 年度ごとの進み具合の順にする。成果指標は報告書の順にすべて並べる（良い・悪いで並べ替えない。最初の10件より後は「さらに表示」）。行（`components/RmSeikaRow.astro`）は沖縄県PDCAの成果指標の行と同じ形で、右に基準値と比べた判定の印と道のりの小さな図（`RmSeikaSpark`。横は R4〜R6 の3枠で、計画期間が1つなので地の色は無い。凡例は `SeikaKey mini rm`）を出す。施策をさがす・取組をさがすの一覧と件数には混ぜない（沖縄県PDCAの公表値と合わせるため）。取組をさがすでは、観光ロードマップでも評価されている取組に札を付け、絞り込める（`/torikumi/data.json` の `plans`）。観光ロードマップの取組（観光ロードマップにしか無いものも含む）は `/keikaku/kanko/torikumi/` でさがし、名前は施策展開のページの取組のカードへのリンクにする（取組ごとのページは無い）。淡い紫の札（`.plan-tag`）で沖縄県PDCAの施策・取組と見分ける。観光ロードマップの施策の番号（1-ア-①）も沖縄県PDCAの番号と同じく名前より目立たせず（`.code-no`）、出典の行で「観光ロードマップの報告書での番号」と説明する。沖縄県PDCAと同じ取組は、取組のページから相互にたどれるようにする。
- 一括交付金の事業は施策のページ（事業のカード `components/IkkatsuCard.astro`。id は `ikkatsuAnchor`）と予算の「一括交付金の事業をさがす」（`/yosan/ikkatsu/`。名前は施策のページの事業のカードへのリンク）、評価検証報告書は基本施策のページに出す。この2つは個別計画ではないので個別計画の入口には置かず、資料の説明は「このサイトについて」に置く（一括交付金は財源の説明のページからも案内する）。一括交付金の事後評価は沖縄県PDCA（主な取組の進捗状況は活動の量、事後評価は事業ごとの成果目標）とは別の評価なので、観光ロードマップと同じく混ぜずに見分ける。事業の行（`components/IkkatsuRow.astro`）とカードには砂色の札（`.ik-tag`）を付け、一括交付金の事業をさがすの頭には「沖縄県PDCAとは別の評価です」の吹き出しを置く。主な取組・部局票の予算事業とは、名前が同じものでも結び付けない（1つの予算事業が複数の取組・施策にまたがり、取組の「順調」と事後評価の「△」が並ぶと利用者が混乱するため）。予算と財源の頭の札でも、一括交付金の金額（部局票）と事後評価の事業の数は別の札にし、何の数字かを書く。

## 9. 意見とシェア

- 意見: `/iken/` に県民意見募集（パブリックコメント）の受付の状態・いつでも使える県の窓口・SNS で話す方法をまとめる。募集の期間と県のページは `lib/iken.ts` の `BOSHU`（新しい募集が出たら書き換える。受付中・終了は**ビルドした日**で決まる）。募集の箱は「募集しています」の告知として書き、終わったら告知の上に「この募集は終了しました」の張り紙（`.harigami`）を重ねる。SNS のシェアは `components/Share.astro` のシェアパネル（白い枠に「シェア」の文字と、Facebook・LINE・X・Threads・Bluesky の順のアイコンだけの丸いボタンを並べる。開く URL は `lib/share.ts`、ロゴは Simple Icons の形を写した `lib/share-icons.ts`）。名前は読み上げ用の文字とツールチップ（`data-tip-value`）で出し、パネルとしてまとめるため外部リンクの印は付けない（`ExtLink` の例外。読み上げの「別のタブで開きます」は付ける）。公開の場の X・Threads・Bluesky にはハッシュタグ `#okinawa_miraima`（`lib/iken.ts` の `HASHTAG`。画面の文字もこれから出す）を付け、Facebook（sharer.php は URL だけ）と LINE（知り合いに送る）には付けない。ページの URL はビルド時に本番のドメイン（`lib/links.ts` の `SITE.url`）で入れる。施策・基本施策・取組・成果指標・部局・将来像・くらしのテーマのページは、終わり（出典の前）に `components/ShareBox.astro`（「この〇〇のページが役に立ったら」の言葉と、いいねのボタン・シェアパネルだけ。説明の文は書かない）を置く（ページの上のほう・パンくずの行には置かない）。投稿の本文は `lib/iken.ts` の `shareText`（施策「〇〇」について）。SNS に書いても県には届かないことは `/iken/` で伝える（フッターは `/iken/` へのリンクだけ）。
- いいね: シェアの枠のシェアパネルの隣に、ハートと「いいね」の丸いボタン（`components/Like.astro`）を置く。押すと、ボタンの上に運営（ロゴのまるい子の顔の印）からのお礼のポップアップを出し、ハートをまるい子の色でぬる。ポップアップは、お礼「ありがとうございます！／励みになります！」（1文ずつの行）を上に、差出人「このサイトの運営（Code for Okinawa）」を下に署名のように小さく1行で置く（`lib/like.ts` の `LIKE_THANKS`・`LIKE_FROM`。尾をハートに向け、用語の説明と同じ線と影）。ポップアップは3.5秒たつか、ほかの場所を押すか、Esc で閉じ、消えるときはすっと薄くなる（0.2秒）（読み上げには `role="status"` の文字で伝える）。押せるのは1回の表示で1回だけ。**件数は画面に出さない**（数を出すと、よく押された施策の順という物差しができ、1章の「全体の内訳を同じ重みで見せる」とぶつかるため。運営が Cloudflare のログで見るだけ。[deploy.md](deploy.md) の7章）。施策への賛成ではなくページへのいいねと読めるように、枠の言葉は「ページが役に立ったら」にする。スマホ（520px 以下）では、いいねとシェアを1行に並べるため、「いいね」と「シェア」の文字を隠してハートの丸とアイコンだけにする（読み上げには「いいね」「この〇〇を SNS でシェア」と伝わる。`Share` の `compact`）。コメントの欄は置かない（話すのは SNS の #okinawa_miraima、県への意見は県の窓口へ）。

## 11. ページごとの並び

- くらしのテーマ（`/theme/<id>/`）: 一覧はトップの節 `/#themes` だけで、一覧のページとナビの項目は置かない。頭は将来像・部局のページと同じ件数の札（`HeadStats`）とドーナツ2枚（`DonutCard`）。施策は将来像 › 基本施策の見出しの下に並べ、成果指標は報告書の順に全部並べて最初の10件より後は「さらに表示」で開く。
- トップ: ヒーロー（ドーナツ2枚）→ さがす → くらしのテーマ → 5つの将来像 → 主要指標で見る、くらしの大きな数字（`ShuyouTrendTop`。5章）→ 県の「判定」の決まり方 → 4年間の推移 → 意見の順。
- 将来像（`/future/<id>/`）: 頭・ドーナツ → 主要指標の移り変わり（`ShuyouTrendList`。5章）→ 施策の判定 → 前の年度からの変化 → 基本施策ごとの進み具合（主な取組の進捗状況の棒。主要指標は前の節にあるので、カードには入れない）→ 成果指標 → 4年間の推移 → くらしのテーマ → 予算の順。前の年度からの変化（`components/Moves.astro`）は、施策の判定の上がった・下がったと、主な取組の遅れから順調に・新しく遅れの2組を、良い・悪いの対で並べる（判定のマス目の「今年の位置」の続きとして、そのすぐ後に置く）。成果指標は基本施策の見出しの下に報告書の順で全部並べ、基本施策ごとに最初の5件より後は「さらに表示」で開く。
- 観光ロードマップ（`/keikaku/kanko/`）: 頭・3枚の札 → 基本施策と施策展開 → 成果指標 → 年度ごとの進み具合 → 沖縄県PDCAとの関係 → 出典の順（将来像のページの「基本施策ごとの進み具合 → 成果指標 → 4年間の推移」と同じ流れ）。
- 基本施策（`/kihon/<id>/`）: 施策のページと同じく、頭の下に目次を置き、主要指標 → 施策 → 主な取組の進捗 → 県のふりかえり（評価検証報告書）の順。
- 成果指標（`/shihyou/<施策ID>/<指標名の key の SHA-1 の先頭8桁>/`）: シェアや画面の共有で、指標1つだけを見せるためのページ。取組のページと同じく、頭を親の施策の札にぶら下げ、頭 → ゴールまでの道のり（図と表）→ 県による説明 → この指標の施策の主な取組 → 観光ロードマップの同じ指標 → シェア → 出典の順。頭の札に名前・担当・くらしのテーマと、施策ページのカードと同じ「計画値に届いたか → スタート → いま → ゴール」を入れ、PC 幅では頭と図が最初の画面に入るようにする。県による説明は最新の年度を畳まずに出し、前の年度は畳む（R6 までは前期の基準値・計画値に対する説明だと添える）。主な取組は、県の検証票が取組ごとの「対応する成果指標」に施策の成果指標をまとめて書いていて取組ごとには分かれていないので、名前で選んだように見せず「この指標の施策の主な取組」として、指標の最新の報告と同じ年度の施策の取組をまとめて出す（`lib/data.ts` の `torikumiOfSeika`）。その年度の進捗状況の内訳の棒と件数の札をステッカーに入れ、その下に取組の一覧（4年分のスタンプ）を畳まずに並べる。並びは施策ページの取組の並び（良い・悪いで並べ替えない）。図を描けない指標（目標が「〜との差の縮小」など）は、節の名前を「年度ごとの値」にして表を開いて出す。一覧・テーマ・将来像・部局・取組のページから成果指標の名前へのリンクは、このページへ向ける（`seikaHref`）。
- 取組: 4年のうち3年以上遅れた取組などは、取組をさがすの「4年間の様子」の絞り込みで見る（`?pat=delay3` など）。前にあった `/okure/` はこれと重なるので消した。
- 部局（`/bukyoku/<id>/`）: 将来像のページと同じ並び（施策の判定のすぐ後に前の年度からの変化）で、頭の件数の札・ドーナツ・前の年度からの変化の部品 `HeadStats`・`DonutCard`・`Moves` も同じものを使う。最後の一覧は成果指標と施策で、部局の取組は取組をさがす（`?dept=`）へ案内する。部局がかかわる施策は、関係部等に名前がある施策と、関係部等には無いがその部局の取組がある施策（`lib/data.ts` の `shisakuDepts`。部局の一覧の数と施策をさがすの部局の絞り込みも同じ数え方）で、一覧では2つに分けて見せる。取組・成果指標の所管部課のリンクは、部局のページの課ごとの図のその課の行へ飛ぶ（`sectionHref`）。
- 予算と財源（`/yosan/`）: 財源の推移・一括交付金の事業と事後評価・部局と将来像・大きな予算事業・データの注意の順。予算事業の行は `components/BudgetItem.astro`。
- 意見（`/iken/`）: トップの最後とフッターから入る。
- 施策の判定の移り変わりの頭のリンクは、上がった・下がったの2つだけで、3年続けて遅れは絞り込みだけに置く。

## 12. 動き

サイトを楽しく、分かりやすくするために動きを付ける。ただし、表示が遅くなる・ガタつく・読む手間が増える動きは付けない。

- **意味のある動きだけ。** 付けるのは、押した・変わったの手ごたえ、図を読む順（スタート → いま → ゴール）、どこからどこへ移ったか、の3つ。飾りだけの動き、ずっと動き続けるもの（ふわふわ浮く・点滅・ループ）、数字のカウントアップ（読めるまで待たされ、途中の数がスクリーンショットや印刷に写る）、スクロールに合わせて要素を出す動き（速くスクロールすると空白になる）、パララックスは使わない。
- **1回だけ短く。** ボタンや吹き出しは0.1〜0.25秒、図は描き終わるまで0.8秒ほど。
- **見た目だけを動かす。** transform・scale・opacity・clip-path・SVG の線の描き方だけを動かし、幅・高さ・位置などレイアウトにかかわるものは動かさない（ずれ・ガタつきが起きないように）。
- **ふだんの見た目は動き終わった形。** キーフレームには始まりの形だけを書く。端末で動きを減らす設定（`prefers-reduced-motion: reduce`）・印刷・対応していないブラウザでは、はじめから動き終わった形で見える。`make shot` も動きを減らす設定で撮る。
- **状態の区分はどれも同じ動き。** 遅れだけを揺らす・順調だけを光らせる、はしない（1章）。
- 動きの見た目は `styles/global.css` の「動き」に1か所でまとめ、スクリプトから動かすもの（件数のはね・押して出した行）は `scripts/motion.ts` を使う。外のライブラリは足さない。

いま付けている動き:

- ページを移るとき: 前のページと次のページを0.16秒で重ねて切り替える（CSS の `@view-transition`。スクリプトは使わない）。ヘッダーは別に動かさない（名前を付けて別に動かすと、下までスクロールしたページから移ったときに上から降りてくるため）。
- 配色の切り替え: ボタンから丸く広げて新しい配色を見せる（`scripts/theme.ts`）。
- 影のある押せるもの（ボタン・トップのテーマの札・判定のマス・親の施策の札・絞り込みの条件のボタン）: 乗せると1px浮いて影が伸び、押すと沈む（`.press`。影の大きさは `--sh`）。一覧の行は浮かせない（数が多くちらつくため。6章）。
- 用語の吹き出しは出るときに少しふくらみ、ツールチップは薄く出る。畳んだ内容を押して開いたときと、「さらに表示」で出した行は、すっと出す（高さは動かさない。# の行き先・印刷で開いたときは動かさない）。
- ドーナツ: ページを読み込んだときに、上から右回りに伸びる（最初の画面にあるものだけが目に入る）。内訳の棒・割合のメーターは動かさない（伸びる動きは要らないと決めた。2026-10）。
- 施策の判定のハンコと4年分のスタンプ（施策・取組のページの頭）: ハンコを押してから、R4 → R7 の順にポンと押す（`components/Stamps.astro` の `pop`）。一覧の行のスタンプは動かさない。
- スクリプトで描く図（成果指標の道のり・活動指標・4年間の推移。`scripts/charts.ts`）: 図が画面に入ったときに1回だけ、計画の道すじとゴールを出したまま、実績の線を始まりから伸ばし、線が届いた年度の点を置き、描き終わってから「いまここ」などの札を出す（カードの「スタート → いま → ゴール」と同じ順）。描き直したとき（幅が変わった・印刷）は動かさない。
- 判定のマス目（`components/JudgeMatrix.astro`）: マスに乗せる・フォーカスすると、そのマスが入る行と列の見出し（取組○%・成果○%）を光らせる。なぜその判定かがマス目だけで読める。
- いいね（`components/Like.astro`。9章）: 押すとハートがポンとはね（0.25秒）、お礼のポップアップが尾のほうから少しふくらんで出る。3.5秒たつ・ほかの場所を押す・Esc で、0.2秒で薄くなって消える。動きを減らす設定では、すぐに出てすぐに消える。
- 絞り込みの件数: 条件を変えて件数が変わると、数字が小さくはねる（開いたときの最初の絞り込みでは動かさない。一覧の行は数が多いので動かさない）。
- ページ内の目次: いま読んでいる節のリンクに印を付ける（`scripts/toc.ts`）。スマホで目次が横にはみ出すときは、そのリンクが見えるように目次だけを横にずらす。
